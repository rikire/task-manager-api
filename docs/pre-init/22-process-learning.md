# 22. Обучение и проверка процесса

**Статус:** принято 2026-10-06, человек. **Область:** 8 «Обучение процесса».

## Потребность

Ошибка агента повторится в следующей сессии, если не изменить систему: агент не помнит прошлых
сессий. При этом новое правило может ничего не менять в поведении. Нужно: превращать каждую
замеченную ошибку в изменение системы, видеть, из-за какого сбоя появилось каждое правило, и уметь
проверить, что правило работает.

## Варианты

- Лестница «во что превращать ошибку» (принцип 1 из [01](01-process-frame.md)): тест → проверка в
  CI → хук → запрет в правах → eval → строка в инструкции.
- Журнал сбоев (паттерн compound engineering у Every: после работы закрепить урок и обновить систему).
- Evals (прогоны агента на кейсах с правилом и без): на каждое правило / только на дорогие сбои.
- Аудит процесса: по календарю / по событию / по требованию.
- Инструменты: `skill-creator`, `claude plugin eval`, `claude plugin validate`, сторонний линтер
  инструкций agnix.

## Решение

### 1. Журнал «сбой → средство»

Один файл (путь — [23](23-documentation.md)). Запись на
каждый замеченный сбой агента:
- ID `FAIL-NNN-<slug>` (журнальный формат, как у ADR и DEBT — [09](09-traceability.md));
- что конкретно произошло;
- к какой известной слабости агента относится (список — [research/README.md](research/README.md),
  раздел 3);
- предполагаемая причина;
- выбранное средство и его уровень на лестнице;
- ссылка на коммит со средством.

Черновик записи пишет агент, когда человек указал на ошибку или сработал стоп-триггер
([13](13-authority.md)); человек подтверждает.

### 2. Средство по лестнице

Строка в инструкции — только если ниже по лестнице ничего не выражается кодом. У каждого нового
правила `Source:` ([08](08-normative-descriptive.md)) указывает на запись журнала: видно, из-за
какого сбоя появилось правило; правило без причины — кандидат на удаление.

### 3. Когда пишется eval

Только если:
- средство — инструкция или скилл (договорённость), а сбой дорогой;
- меняется важное правило и нужно убедиться, что поведение не сломалось.

2–5 кейсов из реальных сбоев, прогон с правилом и без, по 3 раза. Инструмент — `skill-creator`:
в проекте скиллы, а не плагины, и формат его evals несовместим с `claude plugin eval`. Сюда же
eval-кейсы для скилла `architecture` ([11](11-architecture-design.md)): он заменяет часть процесса —
условие прогона из [20](20-skills.md).

### 4. Аудит процесса

**По требованию человека или по предложению агента**, не автоматически. Агент предлагает аудит после
нескольких закрытых изменений, при смене модели или обновлении Claude Code. Что входит:
- прогнать имеющиеся evals;
- найти правила, которые не срабатывали, и правила, чей `Source:` ведёт на давно закрытый сбой без
  повторов, — кандидаты на удаление;
- неиспользуемые скиллы ([20 §8](20-skills.md));
- устаревшие строки в AGENTS.md;
- перезаписать фикстуры хуков после обновления Claude Code ([16](16-guardrails-harness.md)).

Агент готовит отчёт; что удалять и менять — решает человек.

### 5. Инструменты для построения процесса

- `skill-creator` — создание и проверка скиллов ([20](20-skills.md));
- встроенный субагент `claude-code-guide` — ответы по документации Claude Code про хуки и
  настройки, чтобы агент не выдумывал API;
- `claude plugin validate` — синтаксис и схема плагинов;
- unit-тесты хуков ([16](16-guardrails-harness.md)).

Сторонний линтер инструкций agnix пока не берём: независимой оценки его правил нет.

### 6. Кто меняет инструкции

Агент предлагает дифф, человек подтверждает, коммит отдельный ([13](13-authority.md),
[21](21-attribution.md)).

## Обоснование

- Лестница от гарантии к договорённости; агент, который пишет собственные ограждения, может сделать
  хук, пропускающий действие при сбое, — проверять должен не автор
  ([ч.7 §5, §7](research/report/07-guardrails-harness-process.md)).
- Методика evals Anthropic: кейсы из реальных сбоев, сравнение с прогоном без правила, чтение
  транскриптов; для малого проекта — несколько кейсов на дорогие сбои
  ([ч.7 §6](research/report/07-guardrails-harness-process.md)).
- Compound engineering (Every): закрепить урок и обновить систему; данных об эффективности нет
  ([ч.7 §5](research/report/07-guardrails-harness-process.md)).
- Аудит по требованию или предложению, а не автоматически, — решение человека.

## Гарантия

- Журнал, выбор средства, предложение аудита — **Д**; подтверждение — **Ч**.
- `Source:` у правил — **Гф** ([08](08-normative-descriptive.md)).
- Evals — измерение, не гарантия; вердикт — **Ч**.
- Средства с нижних ступеней лестницы (тест, CI, хук, `deny`) — **Г**.

## Где будет реализовано

- Файл журнала сбоев — путь по [23](23-documentation.md); тип ID `FAIL-` — в реестре префиксов.
- AGENTS.md: «замеченный сбой → запись в журнал → средство по лестнице»; предложение аудита.
- Evals — рядом со скиллами (`skill-creator`).
