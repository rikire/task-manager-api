# 30. Комментарии в коде

**Статус:** принято 2026-10-06, человек. **Область:** 4 «Контекст и инструкции».

## Потребность

Агенты склонны комментировать слишком много и пересказывать код; такие комментарии устаревают и
вводят в заблуждение. При этом в коде нужны связи с требованиями, ADR и долгом. Нужно определить,
когда комментарий пишется, что в нём и на каком языке.

## Варианты

- Комментарии «что делает код» / только «почему».
- Закомментированный код: запрещён / разрешён с пометкой.
- Ссылки на артефакты в комментариях: нет / в определённых местах.
- Язык: английский / русский.

## Решение

1. **Комментарий объясняет «почему», а не «что»:** неочевидное решение, ограничение, обходной путь,
   инвариант, подводный камень. То, что видно из кода, не комментируется.
2. **Не бывает:** истории правок в комментариях (она в git) и пересказов вида «увеличиваем
   счётчик».
3. **Закомментированный код** — только временный отладочный, с маркером `DEBUG:`. Pre-commit не
   пропускает коммит, в котором есть маркер `DEBUG:`, — такой код убирается до коммита.
4. **Ссылки в комментариях:**
   - `R-…` — в точке входа поведения ([09](09-traceability.md));
   - в бизнес-логике — пояснение требования, которое реализует этот участок, со ссылкой `R-…`;
   - `ADR-…` — там, где реализовано решение ([12](12-adr.md));
   - `DEBT-…` / `IMP-…` — в маркерах `TODO`, `FIXME`, `HACK` ([10](10-debt-polish-headroom.md)).

   Комментарий обновляется вместе с кодом; CI проверяет, что упомянутые ID существуют.
5. **Документирующие комментарии** (докблоки) — только там, где они дают информацию сверх кода:
   публичный контракт, типы, которые язык не выражает, но которые нужны статическому анализу. По
   стеку — [32](32-stack-tools.md).
6. **Язык — английский:** имена в коде английские, и комментарий читается вместе с ними
   ([23](23-documentation.md)).

## Обоснование

- Плотность комментариев у моделей заметно выше человеческой (Sonar, вендор: 16,4% у Claude 3.7
  Sonnet против 4,4% у GPT-4o); ценность есть у невыводимого — «почему» и подводных камней
  ([ч.3 п.9](research/report/03-weaknesses.md)).
- Исключение для отладочного кода с маркером и проверкой в pre-commit — решение человека.

## Гарантия

- Маркер `DEBUG:` в коммите — **Г** (pre-commit); существование ID — **Гф** (CI).
- «Почему, а не что», пояснения требований, язык — **Д**; проверяет человек при ревью.

## Где будет реализовано

- `.claude/rules/` — правило для путей с кодом.
- Pre-commit — запрет маркера `DEBUG:`; CI — проверка ID.
