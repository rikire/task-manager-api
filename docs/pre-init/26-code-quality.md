# 26. Качество кода и стиль

**Статус:** принято 2026-10-06, человек. **Область:** 6 «Проверка».

## Потребность

Агент делает тяп-ляп, копит запасные ветки и значения по умолчанию, глотает ошибки, пишет своё вместо
библиотеки, раздувает код и повторяется. Инструкции против этого не работают. Нужен единый стиль и
проверки, которые ловят эти сбои машинно.

## Варианты

- Форматтер, линтер, тайпчекер в хуках и CI (гарантия запуска).
- Пороги сложности и дублирования, поиск мёртвого кода в CI.
- Правила кода в инструкциях (договорённость) / с машинной проверкой.
- Хук-напоминание при появлении подозрительных конструкций.
- AI-ревью кода (`/code-review`, CodeRabbit и аналоги) — вероятностное.
- Коммерческий quality gate (Sonar AI Code Assurance).

## Решение

### 1. Проверки по моментам

| Момент ([04](04-definition-of-done.md)) | Что |
|---|---|
| после правки файла (PostToolUse) | форматтер; быстрый линтер по файлу — замечания сразу возвращаются агенту (exit 2 в PostToolUse не блокирует, но передаёт текст агенту) |
| конец хода и pre-commit | линтер, тайпчекер |
| CI | пороги когнитивной сложности функций и дублирования **на новом коде**; поиск мёртвого кода; архитектурные правила ([11](11-architecture-design.md)); мутации ([06](06-test-quality.md)) |

Пороги на старте — по умолчанию инструментов; ужесточаются после замеров.

### 2. Правила кода `RUL-CODE-<slug>`

По возможности каждое проверяется машиной:
- **fail-fast:** не глотать ошибки, без широкого catch, без catch с возвратом значения по умолчанию;
  значение по умолчанию задаётся один раз — на границе, где данные входят в систему. Проверяют
  линтер, тесты сбойных путей ([07](07-requirements-intent.md)), мутации (мутант «вернуть значение по
  умолчанию» должен ловиться тестом).
- **Сначала готовое:** библиотека или стандартная библиотека вместо своего кода (секция «Известные
  решения», [11](11-architecture-design.md)); дубли ловит детектор дублирования.
- **Без мёртвого кода и отладочного вывода** — линтер.
- **YAGNI:** без непрошеной функциональности (обратная трассировка, [09](09-traceability.md)) и без
  абстракции без второй реализации (шлюз простоты, [11](11-architecture-design.md)).
- **Без выдуманных API:** тайпчекер + «проверяй по источнику» ([03](03-agent-instructions.md)).
- **Стиль задаётся конфигурацией форматтера и линтера**, а не текстом.

### 3. Стиль и скиллы под стек — при инициализации

Когда выбран стек, агент по процессу [20](20-skills.md) ищет:
- официальный или общепринятый стиль-гайд языка и фреймворка;
- скиллы с практиками стека (официальные каталоги, затем community).

Приносит карточки кандидатов; выбранный стиль-гайд превращается в конфигурацию форматтера и линтера
плюс короткие правила `RUL-CODE-…` для того, что конфигом не выражается; выбранные скиллы ставятся
по [20](20-skills.md). Решает человек.

### 4. Хук-напоминание

Если в правке появился новый catch или значение по умолчанию, PostToolUse-хук возвращает агенту
напоминание обосновать или убрать. Здесь инструкции, по данным, не работают, поэтому напоминание
приходит в момент действия.

### 5. AI-ревью кода

Опционально: агент предлагает `/code-review` в сводке для ревью ([18](18-human-comprehension.md))
для нетривиальных изменений, с фильтром «только корректность и требования».

### 6. Не берём

Коммерческий quality gate: его условия (покрытие и дублирование на новом коде) воспроизводятся
бесплатными инструментами.

### 7. Критерий выбора стека

Статическая типизация или строгий тайпчекер: бесплатная проверка API и сигнатур ([32](32-stack-tools.md)).

## Обоснование

- 304 тыс. коммитов агентов: 89% найденных проблем — code smells, около четверти живы на последней
  ревизии; промпты против «слопа» снижают многословие на треть, но не скорость деградации
  ([ч.3 п.3](research/report/03-weaknesses.md)).
- Запрет запасных веток и глотания ошибок в CLAUDE.md не помогал (issues #31890, #41957, #21027 в
  anthropics/claude-code); работают синтаксические проверки и тесты сбойных путей
  ([ч.3 п.6](research/report/03-weaknesses.md)).
- «Use hooks for actions that must happen every time with zero exceptions» (вендор); статическая
  типизация — бесплатный сенсор (Böckeler); AI-ревью полезно на 36–74% комментариев, без фильтра
  шумит; коммерческий gate окупается хуже
  ([ч.5 «Качество кода и архитектуры»](research/report/05-architecture-testing-verification.md)).
- Выбор стиля и скиллов при инициализации — решение человека.

## Гарантия

- Форматтер, линтер, тайпчекер, пороги, поиск мёртвого кода — **Г запуска**.
- Правила `RUL-CODE` — **Г** там, где есть машинная проверка; остальное **Д**.
- Хук-напоминание — **Г доставки**.
- AI-ревью — **В**; выбор стиля и скиллов — **Ч**.

## Где будет реализовано

- Конфигурация форматтера, линтера, тайпчекера, порогов — по стеку ([32](32-stack-tools.md)).
- `.claude/settings.json` — PostToolUse: форматтер, линтер по файлу, напоминание о catch и
  значениях по умолчанию.
- `.claude/rules/` — правила `RUL-CODE-*` для путей с кодом.
- CI — пороги сложности и дублирования, поиск мёртвого кода.
