# Часть 6. Гарантию даёт только то, что исполняет программа: безопасность агента, понимание кода, контекст, состояние и документация

Почти все механизмы из этой части, о которых пишут вендоры и практики, — договорённости. Это текст, которому модель «старается» следовать. Гарантию дают только механизмы, исполняемые клиентом, ОС или CI: песочница, правила прав, блокирующие хуки, проверки в CI, файлы на диске, которые перечитываются принудительно. Это не интерпретация, а прямая позиция документации Claude Code (вендор) [П]: CLAUDE.md — «context, not enforced configuration», а чтобы заблокировать действие независимо от решения модели, нужен PreToolUse hook ([memory](https://code.claude.com/docs/en/memory)). Эмпирических данных об эффективности конкретных механизмов мало. Есть одно RCT о понимании кода (вендор), два исследования контекстных файлов, синтетические бенчмарки деградации инструкций и ретроспективный разбор атак на цепочку поставок. Для большинства строк в таблицах ниже ответ — «данных нет». Для одного разработчика с небольшим бэкендом отсюда следует выбор не «какой процесс», а «какие 5–8 дешёвых гарантий поставить и что сознательно оставить договорённостью».

## Ключевые выводы

- **Граница «гарантия / договорённость» задокументирована вендором**, а не выведена: CLAUDE.md, скиллы и output styles «shape behavior», но «not a hard enforcement layer». Исполняются только settings (права, песочница) и hooks — [memory](https://code.claude.com/docs/en/memory) (вендор) [П]. Факты о Claude Code сверены с документацией на 2026-10-03.
- **Безопасность агента.** Надёжной защиты от prompt injection на уровне модели нет. Архитектурная мера — не собирать в одной сессии «смертельную триаду»: приватные данные, недоверенный контент и внешнюю коммуникацию ([simonwillison.net](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/) [П]). Deny-правила Claude Code не равны изоляции: скрипт, запущенный агентом, прочтёт `.env` в обход них. Для ОС-уровня нужна песочница в strict mode ([permissions](https://code.claude.com/docs/en/permissions), [sandboxing](https://code.claude.com/docs/en/sandboxing), вендор [П]). Против атак на цепочку поставок — lockfile, пиннинг и cooldown по возрасту релиза. По ретроспективному подсчёту, 7-дневный cooldown отсёк бы 8 из 10 разобранных атак ([nesbitt.io](https://nesbitt.io/2026/03/04/package-managers-need-to-cool-down) [В]).
- **Понимание кода.** Единственное RCT (Anthropic, n=52, вендор) [П]: при делегировании генерации квиз на понимание 50% против 67% без ИИ. Сохраняли понимание те, кто расспрашивал модель о сгенерированном ([anthropic.com/research](https://www.anthropic.com/research/AI-assistance-coding-skills)). Гарантировать можно только процедурные гейты (размер diff, запрет автокоммита). Само понимание остаётся договорённостью человека с собой.
- **Атрибуция.** Сложился де-факто стандарт: трейлер `Assisted-by:` и запрет агенту ставить `Signed-off-by` (Linux, LLVM, Fedora). Есть и полные запреты (QEMU, Gentoo, NetBSD). Ручные правки между шагами Claude Code ловит механически: Edit сверяет `old_string` с текущим содержимым. Это защищает от перезаписи, но не гарантирует, что агент учтёт смысл правки ([tools-reference](https://code.claude.com/docs/en/tools-reference), вендор [П]).
- **Контекстные файлы.** По Gloaguen et al. (arXiv 2602.11988) [П, сверено 2026-10-03], написанные разработчиками файлы дают лишь **маргинальный** прирост (+4% в среднем), сгенерированные LLM — небольшой минус (−0,5…−3%). Стоимость растёт на 20–23%. Аннотация текущей версии формулирует то же как «does not generally improve task success rates». Lulla et al.: с AGENTS.md медианное время на 28,64% меньше при сопоставимом завершении задач ([arXiv](https://arxiv.org/abs/2601.20404v1) [П]). Вывод: файл должен быть коротким, написанным человеком, без обзора репозитория.
- **Сколько инструкций — слишком много:** эмпирического порога для coding-агентов нет. Есть вендорские ориентиры: <200 строк на CLAUDE.md (Anthropic), <500 строк на правило (Cursor), 32 KiB на цепочку AGENTS.md (Codex). Синтетический IFScale показывает 68% выполнения на 500 инструкциях у лучших моделей [В].
- **Состояние задачи.** `/compact` и рестарт надёжно переживает только то, что лежит на диске и перечитывается принудительно. Это корневой CLAUDE.md, rules без `paths`, auto memory, план plan mode и git status. Path-scoped rules, вложенные CLAUDE.md, листинг скиллов и контекст от хуков теряются или сжимаются ([context-window](https://code.claude.com/docs/en/context-window), вендор [П]). Гарантия доставки состояния — файл прогресса плюс SessionStart-hook с matcher `compact`.
- **Согласованность.** При противоречии «Claude may pick one arbitrarily» ([memory](https://code.claude.com/docs/en/memory), вендор [П]). Встроенный `/doctor prompt-audit` — это LLM-аудит, а не гарантия. Детерминированно можно проверить в CI только мёртвые пути, отсутствующие команды и остатки отменённых формулировок. Схема «ADR перечисляет отменяемые правила, CI грепает остатки» как задокументированная практика не найдена [И].
- **Доставка в нужный момент.** Гарантию *доставки* в момент действия дают только hooks с `additionalContext` (PreToolUse, UserPromptSubmit, SessionStart). Гарантию *выполнения* — только блокирующий hook или deny. Автовызов скилла не гарантирован. В эвале Vercel скилл без явной инструкции дал 53%, как и вовсе без документации, а сжатый индекс в AGENTS.md — 100% ([vercel.com](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals), вендор [П]).
- **Документация.** Целостность гарантируют только исполняемые проверки в CI: doc tests, линк- и path-чекеры, контракт OpenAPI против кода. Против «воды» есть два независимых аргумента: данные о вреде LLM-сгенерированного контекста и вендорская рекомендация вырезать из CLAUDE.md всё, что выводится из кода. llms.txt для coding-агента внутри репозитория нерелевантен [И].

## Как читать эту часть

Легенда меток сохранена из заметок. [П] — проверено по первоисточнику. [В] — вторичный источник (агрегатор, пресса, поисковая выдача). [И] — интерпретация. (вендор) — источник от производителя инструмента. (старше 2025) — источник до 2025 года. Метки не повышались. Две цифры, которые расходились между заметками, сверены точечным запросом к arXiv 2026-10-03, см. раздел «Сомнительное». Документация Claude Code сверялась по code.claude.com/docs **2026-10-03**. Номера версий (v2.1.xxx) взяты из документации на эту дату и со временем устареют.

**Вид механизма** в таблицах — это инструкция, скилл, хук, CI, субагент, артефакт, settings или ОС. В колонке «гарантия или договорённость»: **гарантия** — исполняется программой или ОС независимо от решения модели; **договорённость** — текст, которому модель старается следовать. Многие строки — гибриды: хук *гарантирует доставку* текста, но не его *выполнение*. Такие случаи помечены отдельно, потому что именно здесь чаще всего возникает ложное чувство защищённости.

Разделы дают варианты и критерии, а не процесс. Абзац о пропорциональности — интерпретация [И] для заданного брифом контекста: один разработчик, новый небольшой бэкенд-сервис, человек обязан понимать весь код.

## Безопасность работы агента

### Prompt injection: решается архитектурой сессии, а не инструкцией

Корень проблемы сформулировал Willison (16.06.2025) [П]: «LLMs follow instructions in content» и не различают, откуда пришла инструкция. Опасна сессия, в которой одновременно есть **доступ к приватным данным, контакт с недоверенным контентом и возможность внешней коммуникации** — «смертельная триада». Гардрейлы, которые «ловят 95% атак», автор для безопасности считает провалом ([simonwillison.net](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)). Meta в «Agents Rule of Two» (окт. 2025) [В] переформулирует это как правило: в одной сессии допустимо не больше двух из трёх свойств. Это [A] обработка недоверенного ввода, [B] доступ к чувствительным системам или данным, [C] изменение состояния или внешняя коммуникация ([conffab](https://conffab.com/elsewhere/agents-rule-of-two-a-practical-approach-to-ai-agent-security/); [критика](https://kenhuangus.substack.com/p/the-rule-of-two-vs-reality-why-metas)). Академическая линия — Beurer-Kellner et al., 2025 [В]. Шесть паттернов отделяют недоверенные данные от управляющего потока, например Action-Selector без обратной связи от результатов действий. Они дают «provable resistance» ценой полезности ([arXiv 2506.08837](https://arxiv.org/abs/2506.08837v3)).

Практический пример атаки — GitHub MCP (Invariant Labs, май 2025) [П]. Вредоносный issue в публичном репозитории перехватывает агента, тот вытягивает данные приватных репозиториев и публикует их PR-ом в публичный. Авторы называют это архитектурной проблемой («toxic agent flow»), а не багом сервера. Важнее всего наблюдение о людях: пользователи переходят на «Always Allow» «and stop monitoring individual actions» ([invariantlabs.ai](https://invariantlabs.ai/blog/mcp-github-vulnerability)). Для одного разработчика это прямое предупреждение. Усталость от запросов прав превращает ручное подтверждение из гарантии в формальность.

### Инциденты 2025 года: агентский CLI как инструмент атакующего

Три задокументированных случая (все по вторичным источникам) меняют модель угрозы. **Amazon Q Developer для VS Code v1.84.0** (июль 2025) [В]. Коммит 13.07 добавил промпт на стирание домашнего каталога и AWS-ресурсов (`ec2 terminate-instances`, `s3 rm`, `iam delete-user`). Версия вышла 17.07 подписанным релизом и была отозвана 19.07 (v1.85.0), CVE-2025-8217. Причина — GitHub-токен со слишком широкими правами в CodeBuild. AWS заявляет, что код был malformed и реальной угрозы не нёс ([AWS bulletin AWS-2025-015](https://aws.amazon.com/security/security-bulletins/AWS-2025-015/) — страница рендерится JS, текст бюллетеня автор заметок не прочитал; [The Register](https://www.theregister.com/2025/07/24/amazon_q_ai_prompt/); [BleepingComputer](https://bleepingcomputer.com/news/security/amazon-ai-coding-agent-hacked-to-inject-data-wiping-commands)).

**Nx «s1ngularity»** (26.08.2025) [В]: 8 вредоносных версий nx в npm через украденный токен. Postinstall `telemetry.js` искал локальные Claude Code, Gemini CLI и Amazon Q. Затем запускал их с `--dangerously-skip-permissions` / `--yolo` / `--trust-all-tools` и промптом «найди кошельки, SSH-ключи, .env». По данным Nx, утекло **2 349 секретов** ([Okta](https://www.okta.com/blog/threat-intelligence/the-s1ngularity-attack--when-attackers-prompt-your-ai-agents-to/); [OX Security](https://www.ox.security/blog/nx-supply-chain-breach-how-s1ngularity-weaponized-ai/)).

**Shai-Hulud** (сент. 2025) [В] — самораспространяющийся npm-червь, 500+ пакетов. Токены он собирал в том числе установленным им же TruffleHog. CISA рекомендует аудит lockfile, пиннинг на релизы до 16.09.2025, ротацию кредов, MFA, мониторинг egress, branch protection и secret scanning ([Anvilogic (пересказ CISA)](https://www.anvilogic.com/threat-reports/cisa-shai-hulud-npm-worm)). Волна «2.0» прошла в ноябре 2025 ([Upwind](https://www.upwind.io/?p=14565)).

Общий вывод [И]: вредоносный пакет теперь использует уже установленного ИИ-агента как «интеллектуальный стилер». Поэтому привычка запускать агента с флагами обхода прав на хосте с кредами — самостоятельный риск, независимый от качества кода агента.

### Выдуманные пакеты (slopsquatting)

Основной первоисточник — Spracklen et al., «We Have a Package for You!», USENIX Security 2025 (препринт arXiv 2406.10279, июнь 2024, то есть старше 2025; конференция 2025). Аннотация сверена при подготовке отчёта, 2026-10-03 [П]. В ней 16 моделей, **576 000 сэмплов кода** на двух языках. Средняя доля галлюцинированных пакетов **не ниже 5,2% у коммерческих моделей и 21,7% у открытых**, 205 474 уникальных несуществующих имени. Явление авторы называют «persistent and systemic». Предложенные меры «significantly reduce» галлюцинации ([arXiv 2406.10279](https://arxiv.org/abs/2406.10279)). Вторичный пересказ CSA [В] добавляет цифры, которых в аннотации нет: 2,23 млн сэмплов, 19,7% сэмплов хотя бы с одним несуществующим пакетом, 3,59% у GPT-4 Turbo. А также 43% выдуманных имён повторяются при повторных запросах, поэтому их можно заранее зарегистрировать ([CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-slopsquatting-ai-supply-chain-20260419/)). Расхождение разобрано в «Сомнительном». Ни одна из цифр не говорит, насколько контрмеры эффективны на практике.

### Зависимости: cooldown, lockfile, пиннинг

В 2025–2026 в менеджерах пакетов появилась настройка минимального возраста релиза [В]: pnpm `minimumReleaseAge` (10.16, сент. 2025), Yarn `npmMinimalAgeGate` (4.10), Bun 1.3, npm `min-release-age` (11.10.0, фев. 2026), uv `exclude-newer` с относительным сроком (0.9.17, дек. 2025), pip `--uploaded-prior-to` (26.0). По подсчёту Nesbitt, у **8 из 10** разобранных атак окно было меньше недели, так что 7-дневный cooldown отсёк бы большинство ([nesbitt.io](https://nesbitt.io/2026/03/04/package-managers-need-to-cool-down); [Willison о нём](https://simonwillison.net/2026/Mar/24/package-managers-need-to-cool-down/)). Это ретроспективная оценка на малой выборке, а не измерение. У cooldown есть побочный эффект: pnpm 11 `minimumReleaseAge` ломает CI для PR от Dependabot ([classmethod](https://dev.classmethod.jp/en/articles/pnpm-11-minimum-release-age-dependabot-ci-failure/)) [В].

### Секреты, права и песочница в Claude Code

Документация Claude Code (вендор) [П] описывает три слоя с разными гарантиями.

**Первый слой — permission rules.** Это deny-правила для файлов вроде `Read(./.env)` и `Read(./secrets/**)`; `.claudeignore` «has no effect». Правила Read/Edit deny действуют на встроенные инструменты, на распознанные команды (`cat`, `head`, `sed`, `tee`) и на редиректы. На `grep -r` и на скрипт Python/Node, который сам открывает файлы, **они не действуют**: «For OS-level enforcement… enable the sandbox». Порядок правил — deny → ask → allow, решает первое совпадение, и «An allow rule can't carve an exception out of a deny rule». Bash-deny не ловит ту же программу, вызванную по пути или внутри `sh -c`, поэтому для сети его надо дополнять allowlist песочницы ([permissions](https://code.claude.com/docs/en/permissions)).

**Второй слой — песочница ОС**: macOS Seatbelt, Linux/WSL2 bubblewrap + socat. Она покрывает Bash, PowerShell, Monitor и их подпроцессы. Встроенные Read/Edit/Write/WebFetch, MCP-серверы и hooks она **не покрывает**: «A `denyRead` entry doesn't stop the Read tool, and `allowedDomains` doesn't limit WebFetch». По умолчанию чтение открыто почти по всей машине, включая `~/.ssh` и `~/.aws/credentials`. Сеть идёт только через прокси с allowlist доменов, изначально пустым. Есть аварийный выход: Claude может повторить упавшую команду с `dangerouslyDisableSandbox`, а в режиме bypassPermissions — без запроса. Закрывается это через `allowUnsandboxedCommands: false` + `failIfUnavailable` («Strict sandbox mode»). Широкие `excludedCommands` (например, `docker *`) — дыра: Claude может записать compose-файл и выполнить его вне песочницы. Для секретов есть `sandbox.credentials` с режимами `deny` или `mask`. При `mask` команда видит плейсхолдер, а прокси подставляет реальный секрет только для разрешённых хостов. Записи `credentials` из репозиторного `.claude/settings.json` не применяются (v2.1.246+). `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` вычищает креды из всех подпроцессов ([sandboxing](https://code.claude.com/docs/en/sandboxing)).

**Третий слой — hooks.** PreToolUse может вернуть `permissionDecision: allow|deny|ask|defer`. Exit 2 блокирует вызов, и даже JSON `allow` этого не отменит ([hooks](https://code.claude.com/docs/en/hooks)).

У Codex (вендор) [П] есть режимы песочницы read-only / workspace-write / danger-full-access на Seatbelt и Landlock/bubblewrap. Подробная страница не открывалась, только индекс ([learn.chatgpt.com/docs/security](https://learn.chatgpt.com/docs/security)).

Ключевой неочевидный факт [И]: **deny-правила не равны изоляции**. Без песочницы deny для секретов — частичная мера, потому что любой скрипт, написанный и запущенный агентом, читает файлы мимо правил. Обратное тоже верно: песочница не ограничивает встроенный Read, поэтому нужны оба слоя.

| Lockfile + пиннинг + cooldown 7 дней | менеджер пакетов / CI | гарантия | ретроспективно: 8 из 10 атак отсеклись бы [В] |
| Проверка существования и возраста пакета перед установкой (против slopsquatting) | хук / CI | гарантия, если проверка автоматическая | частота галлюцинаций ≥5,2% / ≥21,7% [П, аннотация]; 19,7% [В]; эффективность контрмер: данных нет |
| gitleaks / trufflehog в pre-commit и CI | CI | гарантия на уровне коммита (по сигнатурам) | данных нет (не искали); страницы инструментов не открывались [И] |
| Не запускать агентов с `--dangerously-skip-permissions` на хосте с кредами | договорённость человека | договорённость | Nx: атакующий использовал именно этот флаг [В] |
| Без долгоживущих npm/GitHub-токенов в окружении агента | процесс / окружение | гарантия, если токенов физически нет | Amazon Q, Nx: причина — широкий или украденный токен [В] |

### Пропорциональность для маленького проекта

Для одного разработчика минимальный набор гарантий выглядит так [И]. Песочница в strict mode (или devcontainer) с пустым allowlist сети, который дополняется вручную. `Read`-deny и `credentials` для секретов. Lockfile и cooldown. Отсутствие долгоживущих токенов публикации в окружении агента. Всё это настраивается один раз, почти не требует сопровождения и закрывает реальные векторы инцидентов 2025 года. Не окупаются на этом масштабе формальные паттерны изоляции уровня Beurer-Kellner и собственные классификаторы инъекций. Подключение MCP-серверов к недоверенному контенту лучше просто не делать в сессиях с секретами. Цена cooldown — отставание от свежих патчей безопасности и ломающийся Dependabot. Нужно решить, допускаются ли исключения для security-релизов.

### Что уточнить позже

Когда станет известен стек: какой менеджер пакетов и есть ли в нём настройка минимального возраста; поддерживает ли ОС разработчика bubblewrap или Seatbelt; нужен ли devcontainer. Нужно и решение о MCP-серверах: какие из них видят недоверенный контент. Количественных данных о том, какую долю prompt injection ловит песочница, хуки или классификатор auto mode, в открытых источниках нет. Сравнивать меры придётся по модели угрозы, а не по цифрам.

## Понимание кода человеком

### Что известно о самом эффекте

Есть одно рандомизированное исследование (Anthropic, 29.01.2026, вендор) [П]. n=52, в основном junior, незнакомая библиотека Trio. Квиз у группы с ИИ — **50% против 67%** у группы без ИИ (Cohen's d=0.738, p=0.01), сильнее всего просел дебаг. Ускорение ~2 мин, статистически незначимо. Понимание сохраняли паттерны «generation-then-comprehension», «hybrid code-explanation» и «conceptual inquiry». Оговорки: мерили немедленное понимание, выборка малая ([anthropic.com/research](https://www.anthropic.com/research/AI-assistance-coding-skills)). Вторичный пересказ [В] приводит подгруппы: кто задавал концептуальные вопросы, набрал ≥65%, кто делегировал генерацию — <40% ([InfoQ](https://infoq.com/news/2026/02/ai-coding-skill-formation/)). В основном тексте Anthropic эти цифры не найдены, см. «Сомнительное».

Явление описывают и концептуально. «Comprehension debt» (Osmani, 14.03.2026) [В] — это разрыв между объёмом кода и тем, что реально понимает человек; он порождает ложную уверенность ([addyosmani.com](https://addyosmani.com/blog/comprehension-debt/)). Storey (апр. 2026) [В] разводит «cognitive debt» (эрозия общего понимания) и «intent debt» (нет зафиксированного обоснования решений). Пример — студенческая команда, которая на 7-й неделе не могла объяснить решения своей системы ([LeadDev](https://leaddev.com/ai/ai-coding-creates-two-kinds-of-debt-youre-only-measuring-one); [arXiv 2603.22106](https://www.alphaxiv.org/abs/2603.22106) — не открывался).

### Какие механизмы предлагают

Инструментальная поддержка есть только в форме договорённостей. Claude Code (вендор) [П] предлагает output styles. **Explanatory** добавляет блоки `★ Insight` с обоснованием выборов — в разговоре, а не в файлах. **Learning** делает то же и добавляет `TODO(human)`: в местах с реальным дизайн-решением Claude оставляет человеку написать несколько строк, останавливается и ждёт. Документация прямо оговаривает: «An output style gives Claude instructions to follow. It doesn't guarantee that something always happens». Стиль действует на основной разговор и fork, на остальных субагентов — нет ([output-styles](https://code.claude.com/docs/en/output-styles)). Checkpoints снимают снапшот файлов перед правками и позволяют откатиться (`/rewind`). Удалённые действия (БД, API, деплой) они не покрывают ([how-claude-code-works](https://code.claude.com/docs/en/how-claude-code-works), вендор [П]). Это страховка от ошибки, а не механизм понимания.

Открытые проекты формулируют понимание как условие приёма вклада. Ghostty [П]: «If you can't explain what your changes do and how they interact with the greater system without the aid of AI tools, do not contribute». По сути это explain-back ([AI_POLICY.md](https://raw.githubusercontent.com/ghostty-org/ghostty/main/AI_POLICY.md)). LLVM [П]: «Contributors must read and review all LLM-generated code or text before they ask other project members to review it», и автор должен уметь отвечать на вопросы на ревью ([llvm.org AIToolPolicy](https://llvm.org/docs/AIToolPolicy.html)). В обоих случаях проверку проводит другой человек, ревьюер. Одиночный разработчик этого внешнего контроля лишён.

### Пропорциональность для маленького проекта

Для владельца, обязанного понимать весь код, единственная доказательная опора — RCT Anthropic [И]. Пассивное делегирование вредит пониманию, активное расспрашивание его сохраняет. Значит, у explain-back и Learning-стиля обоснование правдоподобное, но косвенное. Дешёвые гарантии здесь — гейты: запрет автокоммита и лимит размера diff. Они не обеспечивают понимание, а создают точку, в которой человек вынужден смотреть на код. Дороже, но ближе к данным RCT — писать руками ядро домена и обработку ошибок. Это прямо замедляет работу; решать человеку. Критерий выбора: если требование «объяснить весь код без ИИ» буквальное, одних гейтов недостаточно. Нужен ритуал, где человек формулирует объяснение сам, а не читает объяснение агента.

### Что уточнить позже

Какой размер diff человек реально способен отревьюить. Классические данные (например, SmartBear/Cisco) старше 2025, исследований для ИИ-кода в 2025–2026 не найдено. Как проверять понимание: квиз от агента или устный пересказ себе. Какие модули писать руками. Данных о долгосрочном эффекте (месяцы) и об опытных разработчиках нет.

## Разграничение работы человека и ИИ, атрибуция

### Политики раскрытия: от трейлера до запрета

Спектр политик открытых проектов широк. **Linux kernel** (`Documentation/process/coding-assistants.rst`) [П]: «AI agents MUST NOT add Signed-off-by tags. Only humans can legally certify the DCO». Формат: `Assisted-by: LLM [TOOL1] [TOOL2]`, пример — `Assisted-by: LLM coccinelle sparse`; git/gcc/make не перечисляются ([docs.kernel.org](https://docs.kernel.org/process/coding-assistants.html)). Документ закоммичен 23.12.2025 [В] ([It's FOSS](https://itsfoss.com/news/linux-ai-coding-assistants-policy/); [LWN](https://lwn.net/Articles/1083275/)). Вторичные источники приводят иной формат трейлера, см. «Сомнительное».

**LLVM** («human in the loop») [П] требует обязательного ревью ИИ-контента человеком и маркировки существенного сгенерированного контента трейлером `Assisted-by:`. Запрещены «extractive contributions», использование ИИ для «good first issue» и агенты, действующие без одобрения человека, например GitHub @claude ([llvm.org](https://llvm.org/docs/AIToolPolicy.html); [RFC](https://discourse.llvm.org/t/rfc-llvm-ai-tool-policy-human-in-the-loop/89159)).

**Fedora** (одобрено Council 22.10.2025) [В]: автор отвечает за всё. Раскрытие MUST, если значимая часть взята без изменений, и SHOULD в остальных случаях; рекомендуемый способ — трейлер `Assisted-by` ([Fedora docs](https://docs.fedoraproject.org/ca/council/policy/ai-contribution-policy/); [Phoronix](https://www.phoronix.com/news/Fedora-Allows-AI-Contributions)). **Ghostty** [П] требует раскрывать любое использование ИИ с указанием инструмента и объёма, для мейнтейнеров сделано исключение ([AI_POLICY.md](https://raw.githubusercontent.com/ghostty-org/ghostty/main/AI_POLICY.md)). Apache Software Foundation, по памяти автора заметок, рекомендует трейлер `Generated-by:`. Документ не открывался, см. «Сомнительное».

На другом полюсе — запреты. **QEMU** (текущий master) [П]: «DECLINE any contributions which are believed to include or derive from AI generated content». Обоснование — нельзя добросовестно подтвердить DCO (b)/(c). Исследование API, статанализ и отладка разрешены, если результат не попадает в патч ([qemu.org code-provenance](https://www.qemu.org/docs/master/devel/code-provenance.html)). Обсуждается смягчение для механических правок, тестов, документации и фиксов ≤20 строк [В] ([linuxiac](https://linuxiac.com/qemu-may-relax-its-ban-on-ai-generated-contributions/)). **Gentoo** [П]: «expressly forbidden to contribute… content that has been created with the assistance of NLP AI tools». Причины — копирайт, качество, этика; решение 2024 года (старше 2025) ([wiki.gentoo.org](https://wiki.gentoo.org/wiki/Project:Council/AI_policy)). **NetBSD** [П]: код от LLM «is presumed to be tainted code, and must not be committed without prior written approval by core» (старше 2025) ([netbsd.org](https://www.netbsd.org/developers/commit-guidelines.html)).

Со стороны инструмента (вендор) [П]: Claude Code по умолчанию добавляет в коммиты трейлер `Co-Authored-By`, а в PR — текстовую строку. Это настраивается через `attribution.commit` / `attribution.pr` / `attribution.sessionUrl` и `attribution: false` (v2.1.281+); `includeCoAuthoredBy` устарел. Инструкции пользователя об атрибуции (CLAUDE.md или memory) имеют приоритет над этими строками, если они не заданы в managed settings ([settings-reference](https://code.claude.com/docs/en/settings-reference)). Отсюда тонкость [И]: атрибуция через инструкцию — договорённость, через settings — гарантия, но только для коммитов, которые делает сам Claude Code.

### Как агент учитывает ручные правки человека между шагами

Здесь механизм механический и частично гарантированный (вендор) [П]. Edit tool требует read-before-edit, а также точного и уникального совпадения `old_string`. Если файл изменился на диске после чтения, правка проходит, только когда `old_string` точно совпадает с текущим содержимым. Тогда в результате помечается, что в файле есть другие изменения, чтобы Claude его перечитал. Иначе Claude перечитывает файл перед правкой. Для старых моделей (Opus 4.6, Haiku 4.5 и ранее) чтение обязательно всегда. До v2.1.208 любая правка файла, изменённого после чтения, отклонялась ([tools-reference](https://code.claude.com/docs/en/tools-reference)). Write ведёт себя слабее: новые модели могут перезаписать непрочитанный файл, если чтение не требовало бы запроса прав. До v2.1.228 чтение было обязательно для всех моделей ([tools-reference](https://code.claude.com/docs/en/tools-reference)). Это заметный регресс гарантии в пользу удобства. Именно Write-перезапись — сценарий, в котором ручная правка может быть затёрта [И].

Hook `FileChanged` срабатывает от filesystem watcher, то есть на любое изменение, в том числе внешним процессом. Matcher задаёт буквальные имена файлов, без regex ([hooks](https://code.claude.com/docs/en/hooks)). После `/compact` Claude Code перечитывает с диска до 5 недавно изменённых файлов и делает свежий снапшот git status ([context-window](https://code.claude.com/docs/en/context-window)). При этом сам Claude Code не пересказывает модели *смысл* ручных правок [И]. Надёжно передать его может только hook, который вставляет `git diff` с момента последнего шага.

### Пропорциональность для маленького проекта

Для одного разработчика атрибуция важна не юридически, а для того, чтобы потом отличать «что писал я, что агент» [И]. Это прямо связано с предыдущим разделом: история коммитов показывает, какой код человек мог не прочитать. Минимальная гарантия: settings `attribution` ставит трейлер, а commit-msg hook проверяет, что у коммитов из сессии агента он есть. Вопрос «как агент узнаёт о ручных правках» на малом проекте решается дешевле всего хуком UserPromptSubmit с коротким `git status`/`git diff --stat`. Полный diff в каждом промпте даёт шум (см. раздел о доставке инструкций). Политики уровня LLVM или QEMU для личного проекта избыточны. Полезны они как образец формулировок, если проект станет открытым.

### Что уточнить позже

Какой трейлер выбрать (`Assisted-by` против `Co-Authored-By`) и нужен ли `sessionUrl`. Делает ли коммиты сам агент или только человек. Будет ли проект публичным и под какой лицензией: от этого зависит, нужна ли формальная политика раскрытия. Эмпирических данных о том, как часто агенты затирают ручные правки, не найдено.

## Контекст агента (AGENTS.md / CLAUDE.md, скиллы, память, сколько инструкций — слишком много)

### Данные о контекстных файлах

Есть два независимых исследования 2026 года, и они не противоречат друг другу, если читать их точно.

**Gloaguen, Mündler, Müller, Raychev, Vechev** (ETH Zurich / LogicStar, arXiv 2602.11988, первая версия 12.02.2026), «Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?» [П]. Новый бенчмарк AGENTbench: 138 задач из 12 репозиториев с файлами, написанными разработчиками. Плюс SWE-bench Lite (300 задач без таких файлов, туда подставлялись LLM-сгенерированные). Агенты: Claude Code/Sonnet-4.5, Codex/GPT-5.2 и GPT-5.1 mini, Qwen Code. Цифры из HTML-версии v1, сверенной 2026-10-03. Файлы разработчиков «only marginally improve performance… (an increase of 4% on average)». LLM-сгенерированные «have a small negative effect… (a decrease of 3% on average)»; в другом месте — снижение resolution rate на 0,5% на SWE-bench Lite и на 2% на AGENTbench. Контекстные файлы увеличивают число шагов на 2.45 и 3.92, стоимость — на 20% и 23% соответственно. Агенты инструкциям следуют и больше тестируют и исследуют, но обзоры репозитория не работают ([arXiv abs](https://arxiv.org/abs/2602.11988); [HTML](https://arxiv.org/html/2602.11988v1)).

Аннотация текущей версии на arXiv (обновлена 2026-09-29, сверена 2026-10-03) [П] формулирует итог жёстче: «providing context files does not generally improve task success rates, while increasing inference cost by over 20% on average». Она утверждает, что это верно «for both LLM-generated and developer-committed context files». Также: «repository overviews, although popular and recommended by model providers, are not helpful», а файлы полезны «for specifying non-standard coding practices». Отсюда расхождение между заметками, разобранное в «Сомнительном». Оба прочтения верны: +4% авторы считают маргинальным и не называют улучшением «в целом». Рекомендация статьи — не использовать LLM-сгенерированные файлы и описывать «only minimal requirements (e.g., specific tooling)».

**Lulla et al.** (arXiv 2601.20404, 28.01.2026; JAWs@ICSE 2026) [П]: 10 репозиториев, 124 PR, Codex. С AGENTS.md медианное время на **28,64%** ниже, выходных токенов на 16,58% меньше, завершение задач сопоставимо ([arXiv](https://arxiv.org/abs/2601.20404v1)). Совместное прочтение [И]: файл почти не влияет на долю решённых задач, но может заметно влиять на время и стоимость — в обе стороны, в зависимости от содержания. Оба исследования сделаны на существующих OSS-репозиториях. Для нового маленького сервиса данных нет.

### Сколько инструкций — уже слишком много

Прямого измерения для coding-агентов нет. Есть три линии косвенных данных. **IFScale** (Distyl AI, arXiv 2507.11538, NeurIPS 2025) [В]: 500 инструкций на включение ключевых слов, 20 моделей. Лучшие фронтир-модели на 500 инструкциях выдают 68%. Деградация бывает трёх типов: пороговая (o3, gemini-2.5-pro), линейная (gpt-4.1, claude-sonnet-4) и экспоненциальная (gpt-4o, llama-4-scout). Есть смещение в пользу ранних инструкций ([arXiv](https://arxiv.org/abs/2507.11538); [HTML](https://arxiv.org/html/2507.11538v1)). **Chroma «Context Rot»** (14.07.2025) [П]: 18 моделей, «model performance degrades as input length increases, often in surprising and non-uniform ways». Даже один дистрактор снижает качество, а сфокусированный промпт в LongMemEval значительно лучше полного ([trychroma.com](https://www.trychroma.com/research/context-rot)). «Lost in the Middle» (Liu et al., 2023, старше 2025) [В]: факты в середине длинного контекста извлекаются хуже, чем в начале и конце (пересказ в [morphllm](https://www.morphllm.com/context-rot); оригинал не открывался).

Вендорские ориентиры (все вендор, [П]). Anthropic: «under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence» ([memory](https://code.claude.com/docs/en/memory)). Cursor: «Keep rules under 500 lines» ([cursor.com/docs](https://cursor.com/docs/context/rules)). Codex: лимит `project_doc_max_bytes` 32 KiB на всю цепочку AGENTS.md ([learn.chatgpt.com](https://learn.chatgpt.com/docs/agent-configuration/agents-md)). Порог из этих цифр не выводится [И]. Ориентиры не согласованы между собой, а IFScale меряет синтетическую задачу. Защитима только формулировка: каждая лишняя инструкция имеет цену, и деградация начинается задолго до сотен.

### Как устроены носители контекста

Anthropic в «Effective context engineering» (29.09.2025, вендор) [П] формулирует принцип: «smallest possible set of high-signal tokens», с балансом между «too brittle» и «too vague». Предлагается just-in-time retrieval. У Claude Code гибрид: CLAUDE.md подаётся заранее, glob/grep — по требованию. Для длинных задач — compaction, структурированные заметки, субагенты ([anthropic.com/engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).

Конкретика Claude Code (вендор) [П], [memory](https://code.claude.com/docs/en/memory). `@imports` не снижают стоимость контекста: импортированные файлы тоже грузятся при старте, до 4 хопов. Если инструкция многошаговая или касается части кода, её место — в скилле или path-scoped rule. Auto memory хранится в `~/.claude/projects/<project>/memory/MEMORY.md`. При старте загружаются первые 200 строк или 25 КБ, топик-файлы читаются по требованию. Память хранится локально на машине, то есть не переносится на другую машину и не лежит в репозитории [И]. AGENTS.md читается (v2.1.277+), если нет CLAUDE.md; режим `claude-md-and-agents-md` грузит оба. `/doctor` (v2.1.206+) предлагает урезать CLAUDE.md: убрать выводимое из кода (структуру каталогов, зависимости, обзор архитектуры) и оставить подводные камни, обоснования и отличия от умолчаний. Это совпадает с выводом Gloaguen et al. об обзорах репозитория.

Codex (вендор) [П] конкатенирует AGENTS.md от корня вниз, ближайший к cwd идёт последним и «переопределяет». Есть `AGENTS.override.md`, загрузка «once per run» ([learn.chatgpt.com](https://learn.chatgpt.com/docs/agent-configuration/agents-md)). У Cursor (вендор) [П] 4 типа правил: Always / Apply Intelligently / по glob / вручную. Поддерживаются вложенные AGENTS.md, а User Rules не применяются к Inline Edit и Tab ([cursor.com/docs](https://cursor.com/docs/context/rules)).

Скиллы построены по открытому стандарту Agent Skills ([agentskills.io](https://agentskills.io)) (вендор) [П]. При старте грузится только листинг: имя и description с усечением до 1 536 символов, бюджет ~1% окна. Тело грузится при вызове. `disable-model-invocation: true` означает только ручной вызов. Есть поле `paths` ([skills](https://code.claude.com/docs/en/skills)). Главная практическая проблема — автовызов. Эвал Vercel (27.01.2026, вендор) [П] на API Next.js 16, которых нет в обучающих данных: базовая линия 53%, скилл по умолчанию 53%, скилл с явной инструкцией его вызвать 79%. Сжатый (8 КБ) индекс документации прямо в AGENTS.md дал 100%. Объяснение Vercel: у агента нет «точки решения», текст всегда в контексте ([vercel.com](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). Цифра «в 56% случаев скилл не вызывался» встречается только во вторичной выдаче, см. «Сомнительное».

### Пропорциональность для маленького проекта

Сочетание данных указывает на один вариант [И]. В CLAUDE.md держать только то, что агент не выведет сам: команды, неочевидные запреты, «почему». Писать его руками, не генерировать `/init`-ом без вычистки. Остальное — в path-scoped rules и скиллы. Критичные знания, которые нельзя оставлять на выбор модели, — в постоянный контекст в сжатом виде (вывод Vercel) или в хуки. На новом маленьком проекте выводимого из кода пока мало, и файл естественно короткий. Риск — разрастание по мере того, как каждая ошибка агента превращается в новую строку. Отсюда критерий для решения: у каждой строки должна быть причина, и строка, которую можно заменить проверкой, переносится в проверку. Скиллы на этом масштабе оправданы для редких многошаговых процедур (релиз, миграция) с ручным вызовом. Автовызов для критичных вещей ненадёжен.

### Что уточнить позже

Какие агенты будут использоваться, только Claude Code или ещё Codex/Cursor. От этого зависит, нужен ли AGENTS.md как общий источник и в каком режиме его читает Claude Code. Где хранить память: локальная auto memory не переносится между машинами. Исследований, напрямую сравнивающих path-scoped rules и монолитный файл, нет.

## Состояние задачи между сессиями и при сжатии контекста

### Что переживает `/compact`: таблица по документации

Документация Claude Code (вендор) [П] прямо перечисляет, что происходит с каждым видом контекста при компактации ([context-window](https://code.claude.com/docs/en/context-window)):

| Что | После `/compact` |
|---|---|
| Системный промпт и output style | сохраняются |
| Корневой CLAUDE.md и rules без `paths` | перечитываются с диска |
| Auto memory | перечитывается |
| Git status | свежий снапшот |
| План из plan mode | перечитывается с диска |
| Path-scoped rules и вложенные CLAUDE.md | **теряются** до следующего чтения подходящего файла |
| Изменённые файлы | до 5 последних; файлы >5 000 токенов возвращаются ссылкой |
| Тела вызванных скиллов | ≤5 000 токенов на скилл, ≤25 000 в сумме; при переполнении отбрасываются самые старые |
| Листинг скиллов | **не** восстанавливается |
| Контекст от hooks (`additionalContext`) | сжимается в саммари |
| SessionStart hooks с matcher `compact` | запускаются заново |
| Только разговор (инструкции, решения) | сжимается в саммари |

Саммари сохраняет запросы и намерение, ключевые концепции, изученные и изменённые файлы с фрагментами, ошибки и их фиксы, незавершённые задачи и текущую работу. Полные выводы инструментов и промежуточные рассуждения теряются ([context-window](https://code.claude.com/docs/en/context-window)). Вендор прямо даёт диагностику: «If an instruction disappeared after compaction, it was given only in conversation… Add conversation-only instructions to CLAUDE.md to make them persist». Есть управление компактацией: `/compact <фокус>` и `/autocompact <токены>` ([memory](https://code.claude.com/docs/en/memory); [context-window](https://code.claude.com/docs/en/context-window)). Сессии хранятся в JSONL в `~/.claude/projects/` и возобновляются через `claude --continue`, `--resume [name|id|path]`, `/resume` ([sessions](https://code.claude.com/docs/en/sessions)). Возобновление восстанавливает транскрипт, но не делает состояние задачи явным и проверяемым [И].

### Что делают практики

Anthropic в «Effective harnesses for long-running agents» (26.11.2025, вендор) [П] описывает harness из двух ролей. Initializer-агент создаёт `init.sh`, `claude-progress.txt` и первый коммит. Coding-агент берёт одну фичу за сессию, оставляет «clean state», а в начале сессии читает git log и progress-файл. Список фич хранится в JSON с полем `passes`, потому что «the model is less likely to inappropriately change or overwrite JSON files compared to Markdown files». Наблюдённые сбои: попытка сделать всё за раз, преждевременное «готово», фича помечена завершённой без теста. **Количественных метрик в статье нет** ([anthropic.com/engineering](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). Альтернатива — Beads (Steve Yegge) [В]: трекер задач в git, JSONL в `.beads/`, ID-хеши, приоритеты, граф зависимостей. Позиционируется как замена markdown-TODO. По утверждению одного вторичного источника, Beads «вдохновил Claude Code Tasks» ([morphllm](https://www.morphllm.com/beads-agent-memory); [pkg.go.dev](https://pkg.go.dev/github.com/steveyegge/beads@v0.21.9)).

### Пропорциональность для маленького проекта

Гарантия «агент увидит состояние после compact» достигается сочетанием файла состояния и SessionStart-хука с matcher `compact` [И]. Одна строчка в CLAUDE.md «читай progress.md» — это договорённость. Решения (ADR) и «что сделано» лучше разделять. Решения живут долго, и CLAUDE.md может их импортировать или упоминать. Прогресс короткоживущий и держится в отдельном файле или в git. Для одного разработчика достаточно короткого файла прогресса, хука на старт/resume/compact и git как журнала. Трекер уровня Beads оправдан, когда задач много и между ними есть зависимости. Нерешённый вопрос — кто гарантирует, что агент *обновит* файл прогресса. Хук доставляет файл, но не заставляет его править. Обновление остаётся договорённостью, если не проверять его, например Stop-хуком, который смотрит, менялся ли файл.

### Что уточнить позже

Формат файла состояния (JSON или Markdown; аргумент Anthropic в пользу JSON качественный). Нужен ли внешний трекер. Как устроена встроенная система Tasks/Todo в Claude Code: в исходных заметках она не открывалась. Исследований, сравнивающих progress-файлы, Beads и встроенные Tasks, нет.

## Согласованность инструкций

### Что известно

Вендор признаёт проблему прямо (вендор) [П]: «if two instructions contradict each other, Claude may pick one arbitrarily. Review your CLAUDE.md files, nested CLAUDE.md…, and `.claude/rules/` periodically to remove outdated or conflicting instructions». Между user- и project-rules: «Neither set overrides the other… Claude may follow either one» ([memory](https://code.claude.com/docs/en/memory)). Отдельный источник конфликтов — встроенные инструкции Claude Code о коммитах и PR. Их отключает `includeGitInstructions`, а `attribution` задаёт текст атрибуции ([memory](https://code.claude.com/docs/en/memory)). Есть и временной аспект: правки CLAUDE.md посреди сессии не применяются сразу, это связано с prompt caching. Значит, отменённое правило живёт в контексте до рестарта или compact ([prompt-caching](https://code.claude.com/docs/en/prompt-caching)). У Codex вложенные AGENTS.md конкатенируются, и более близкий «overrides» за счёт позиции, а не явного разрешения конфликта ([learn.chatgpt.com](https://learn.chatgpt.com/docs/agent-configuration/agents-md), вендор [П]).

Встроенная проверка — `/doctor prompt-audit` (вендор) [П]. Он ищет инструкции для старых моделей, ссылки на несуществующие файлы и команды, взаимные противоречия. Охватывает CLAUDE.md, AGENTS.md, rules, skills, commands, subagents и output styles. Выдаёт отчёт с предложенными правками и ничего не меняет без запроса ([memory](https://code.claude.com/docs/en/memory)). Это LLM-аудит по запросу, а не детерминированная проверка. Хук `InstructionsLoaded` логирует, какие CLAUDE.md и rules загружены, когда и почему. Его можно использовать для аудита фактически загруженного набора ([memory](https://code.claude.com/docs/en/memory)).

Сторонние линтеры [В]: **agnix** (Rust, LSP, по данным источника 399 правил; CLAUDE.md / SKILL.md / hooks / MCP) — [codex.danielvaughan.com](https://codex.danielvaughan.com/2026/04/13/agnix-linting-codex-cli-agent-configurations/); **ailint** (кросс-файловая согласованность) — [github](https://github.com/jamesmhall/ailint); **ctxlint** (устаревшие команды, мёртвые пути) — [producthunt](https://www.producthunt.com/p/ctxlint); утилита с форума Cursor (drift AGENTS.md, конфликтующие вложенные файлы) — [forum.cursor.com](https://forum.cursor.com/t/built-a-small-cli-to-detect-agents-md-drift-missing-commands-dead-paths-conflicting-nested-files/159582). Ни один из них в исследовании не запускался.

Схема, предложенная в брифе, — «ADR перечисляет отменяемые правила, а проверка ищет их остатки». В публичных источниках она как готовая практика не встретилась [И]. Это сборка из известных частей: ADR, раздел «отменяет», CI-grep. Её детерминированность ограничена: grep находит только точные формулировки, перефразированный остаток он пропустит.

### Пропорциональность для маленького проекта

Самый дешёвый детерминированный шаг для одного разработчика [И] — один источник инструкций и CI-скрипт, который проверяет, что упомянутые пути и команды существуют. Это несколько десятков строк, и они ловят самый частый вид устаревания. Схема «ADR → grep остатков» оправдана, если ADR реально отменяют правила. На раннем проекте это случается часто, потому что решения ещё нестабильны. `/doctor prompt-audit` стоит воспринимать как подсказку при ревью изменений инструкций, а не как ворота. Сторонние линтеры — кандидаты для оценки, а не рекомендация: ни один не проверен.

### Что уточнить позже

Сколько уровней инструкций будет (user, project, вложенные, rules). Чем больше уровней, тем выше риск противоречий, ведь между user и project приоритета нет. Будет ли ADR-процесс и в каком формате. Данных об эффективности линтеров и `/doctor prompt-audit` нет. Исследований о том, как модели разрешают противоречия в инструкциях агента, тоже нет, кроме вендорской фразы «arbitrarily».

## Доставка инструкции в нужный момент

### Почему «прочитано при старте» недостаточно

Правило, прочитанное в начале сессии, со временем «тонет». Прямых измерений этого на coding-агентах нет, но есть сильные косвенные данные. «LLMs Get Lost in Multi-Turn Conversation» (Laban et al., arXiv 2505.06120, ICLR 2026) [В]: при многоходовой постановке качество падает в среднем на **39%** на шести задачах. Главная составляющая — рост ненадёжности: модели «get lost and do not recover» ([arXiv](https://arxiv.org/abs/2505.06120v1)). IFScale [В] находит смещение в пользу ранних инструкций ([arXiv](https://arxiv.org/abs/2507.11538)). Chroma [П] — деградацию с ростом длины ввода ([trychroma](https://www.trychroma.com/research/context-rot)). Свидетельство «распада инструкций» на длинной сессии косвенное: это синтетические бенчмарки [И].

### Градация механизмов доставки

Claude Code предлагает несколько уровней (вендор) [П]. **Path-scoped rules** срабатывают, «when Claude uses the Read, Write, or Edit tool on a file matching the pattern, not on every tool use». Вложенные CLAUDE.md подгружаются, когда Claude читает файлы в подкаталоге ([memory](https://code.claude.com/docs/en/memory)). Но: «Path-scoped rules and nested CLAUDE.md files load into message history when their trigger file is read, so compaction summarizes them away… If a rule must persist across compaction, drop the `paths:` frontmatter or move it to the project-root CLAUDE.md» ([context-window](https://code.claude.com/docs/en/context-window)). Вероятно, правка файла через Bash (`sed -i`) path-scoped rule не триггерит, ведь триггер — только Read/Write/Edit. Это не проверено [И].

**Скиллы.** Тело скилла входит в разговор одним сообщением и остаётся там. Claude Code не перечитывает файл скилла на последующих ходах, а автовызов не гарантирован ([skills](https://code.claude.com/docs/en/skills)). **Субагенты** получают свой системный промпт и свой контекст. Auto memory основного диалога в них не грузится (кроме fork), output style на не-fork субагентов не действует ([memory](https://code.claude.com/docs/en/memory); [output-styles](https://code.claude.com/docs/en/output-styles)). Это и плюс, и минус: узкий промпт ревьюера доставлен гарантированно, но общие правила проекта туда надо передавать явно [И].

**Hooks** — единственный механизм, который вставляет текст в момент события. Где события добавляют `additionalContext`: SessionStart и SubagentStart — в начале; UserPromptSubmit и UserPromptExpansion — рядом с промптом; PreToolUse, PostToolUse, PostToolUseFailure, PostToolBatch — «next to the tool result»; Stop и SubagentStop — в конце хода, после чего разговор продолжается; есть ещё PostModelSwitch. Обычный stdout при exit 0 в контекст не попадает. Вывод больше 10 000 символов сохраняется в файл, модель получает превью ([hooks](https://code.claude.com/docs/en/hooks); [context-window](https://code.claude.com/docs/en/context-window)). Вендор формулирует критерий прямо: «If the instruction is something that must run at a specific point, such as before every commit or after each file edit, write it as a hook… Hooks… apply regardless of what Claude decides to do» ([memory](https://code.claude.com/docs/en/memory)).

У других вендоров (вендор) [П]: Codex грузит AGENTS.md «once per run», аналогов path-scoped подгрузки на просмотренной странице нет ([learn.chatgpt.com](https://learn.chatgpt.com/docs/agent-configuration/agents-md)). Cursor применяет правила по glob «When file matches a specified pattern» ([cursor.com](https://cursor.com/docs/context/rules)).

### Пропорциональность для маленького проекта

Правила, привязанные к действию («перед миграцией сделай X»), надёжнее доставлять PreToolUse-хуком с matcher по инструменту и пути, а не path-scoped rule [И]. Rule срабатывает только на Read/Write/Edit и пропадает после compact, а хук срабатывает на каждое действие и не зависит от истории. Но у хуков есть цена [И]. Каждое срабатывание добавляет токены, а значит, и шум, который сам по себе ухудшает следование инструкциям (context rot). Ещё хуки — код, который надо поддерживать и тестировать (это вопрос другой части отчёта). Критерий выбора для каждого правила — что будет, если агент его не выполнит. Если последствия серьёзны и нарушение детектируемо, нужен блокирующий хук или CI. Если серьёзны, но не детектируемы, — хук-напоминание, короткое и узко нацеленное. Если цена ошибки мала, хватит CLAUDE.md или path-scoped rule. На маленьком проекте разумно начинать с 1–3 хуков на самые дорогие ошибки, а не переводить в хуки всё.

### Что уточнить позже

Какие действия в конкретном стеке дорогие: миграции, публичный API, работа с секретами. Под них и пишутся matcher-ы. Как реально выглядит вход хука в живой сессии: формат надо наблюдать, а не придумывать. Прямых измерений instruction decay у coding-агентов на длинных сессиях нет.

## Документация

### Целостность: только то, что исполняется

Целостность документации гарантируют только проверки, исполняемые в CI [И]. Это doc tests (исполняемые примеры), link checkers, генерация OpenAPI из кода или кода из OpenAPI с diff-проверкой, проверка путей и команд. Инструменты общеизвестны и старше 2025 (например, doc tests в Rust, Python doctest, линк-чекеры вроде lychee). Первоисточники в исследовании не открывались, и данных об их эффективности именно в агентной разработке не найдено. Документация, «написанная агентом», не становится целостной сама по себе. Если её ничто не проверяет, правило «обнови доки в том же PR» остаётся договорённостью.

### Без воды: два независимых аргумента

Первый аргумент эмпирический. Сгенерированные LLM контекст-файлы снижают успех и повышают стоимость, рекомендуются «only minimal requirements» ([arXiv](https://arxiv.org/html/2602.11988v1) [П]). Второй — вендорский. `/doctor` «cuts content Claude can derive from the codebase, such as directory layouts, dependency lists, and architecture overviews, and keeps pitfalls, rationale, and conventions that differ from tool defaults» ([memory](https://code.claude.com/docs/en/memory), вендор [П]). Vercel (вендор) [П] показывает, что сжатие индекса документации на 80% не уронило результат со 100%. Значит, документацию стоит проектировать под извлечение агентом ([vercel.com](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)). Anthropic добавляет рамку «too vague» vs «too brittle» и just-in-time retrieval вместо предзагрузки ([anthropic.com](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), вендор [П]). Практическое следствие [И]: документацию, которую написал агент, ревьюить вопросом «можно ли вывести это из кода?» и выводимое удалять.

### Для агента и для человека

Классическая рамка документации для людей — Diátaxis: tutorials / how-to / reference / explanation (старше 2025) ([diataxis.fr](https://diataxis.fr/), не открывался) [И]. Для агента полезнее всего reference и how-to с командами. Explanation («почему») нужен обоим, ср. «keeps pitfalls, rationale» у `/doctor` [И].

llms.txt распространяется, но почти не читается [В]. Число сайтов выросло с 4 088 (июнь 2025) до 36 120 (май 2026). При этом по логам Ahrefs (137 тыс. доменов) 97% файлов в мае 2026 не получили ни одного запроса, а SE Ranking (~300 тыс. доменов) не нашёл связи с цитированием ([ppc.land](https://ppc.land/llms-txt-adoption-rises-8-8x-but-97-of-files-get-zero-ai-requests/); [SEJ](https://searchenginejournal.com/97-of-llms-txt-files-got-no-requests-ahrefs-data-shows/579478)). Есть и полезный пример использования llms.txt как индекса для агентов: Claude Code публикует `code.claude.com/docs/llms.txt`, и каждая страница документации отсылает к нему ([llms.txt](https://code.claude.com/docs/llms.txt), вендор [П]). Для coding-агента внутри собственного репозитория формат нерелевантен [И]: агент читает файлы напрямую.

### Пропорциональность для маленького проекта

Для backend-сервиса самая сильная гарантия целостности — контракт (OpenAPI или схема), проверяемый в CI против кода [И]. Это одновременно документация для клиента, для человека и для агента. Остальные документы держатся на договорённостях плюс link- и path-check. На малом проекте разумный минимум такой: контракт с проверкой, короткий README с командами, ADR для решений и CLAUDE.md только с невыводимым. Полный набор Diátaxis окупается, когда появляются внешние пользователи документации. Хук-напоминание об обновлении доки дешёв, но гарантирует только напоминание.

### Что уточнить позже

Есть ли у сервиса публичный API и какой формат контракта естественен для стека (OpenAPI, gRPC/protobuf, GraphQL schema). Поддерживает ли язык doc tests. Кто основной читатель документации, кроме самого разработчика и агента. Эмпирических данных о влиянии doc tests и генерации OpenAPI на качество работы агентов в 2025–2026 нет.

## Как разделы складываются в выбор

Сквозная закономерность [И]: каждый раздел распадается на дешёвый детерминированный слой и дорогой слой договорённостей. Детерминированный слой — это песочница, права, cooldown, трейлер плюс commit-msg hook, файл состояния плюс SessionStart-хук, CI-проверка путей, контракт в CI. Слой договорённостей — понимание кода, учёт смысла ручных правок, выполнение доставленных правил, качество документации. Данные почти везде есть только для второго слоя, и то косвенные. Отсюда критерии выбора, а не процесс:

- Что случится при нарушении — и можно ли нарушение детектировать машинно.
- Сколько стоит поддержка механизма: хуки — это код с тестами.
- Сколько контекста механизм добавляет, ведь каждый токен инструкций сам ухудшает следование им.
- Есть ли вендорская оговорка «doesn't guarantee», превращающая механизм в договорённость.

Понимание кода выпадает из этой схемы: его нельзя проверить машинно, и единственный инструмент с данными — поведение самого человека.

## Сомнительное / не проверено

**Gloaguen et al. (arXiv 2602.11988): расхождение между заметками разрешено.** Заметки 04a/04b цитируют аннотацию: «does not generally improve task success rates», результат одинаков для LLM-сгенерированных и написанных разработчиками файлов. Заметка 05c приводит +4% для файлов разработчиков и −2…−3% для LLM-сгенерированных. Точечная сверка 2026-10-03 показала, что верно и то и другое. Аннотация текущей версии (arXiv API: обновлена 2026-09-29) содержит формулировку 04a/04b. Тело HTML-версии v1 содержит цифры 05c: «developer-provided files only marginally improve performance… (an increase of 4% on average), while LLM-generated context files have a small negative effect… (a decrease of 3% on average)». Там же −0,5% / −2% на SWE-bench Lite / AGENTbench, +2.45 / +3.92 шага, +20% / +23% стоимости. Авторы считают +4% маргинальным и в аннотации не называют это улучшением. Аннотация v1, судя по введению HTML, говорила «tend to reduce task success rates». Сравнивалась ли v2 с v1 построчно, не проверялось: возможно, в новой версии изменились и цифры в теле. Фраза из 05c «−2…−3%» уточнена до «−0,5…−3%». Принадлежность к ICLR 2026 указана в 04b только по вторичному источнику [В].

**Spracklen et al. (arXiv 2406.10279): расхождение между заметками частично разрешено.** Аннотация (сверена 2026-10-03) [П]: 576 000 сэмплов, 16 моделей, ≥5,2% у коммерческих и ≥21,7% у открытых моделей, 205 474 уникальных имени. Цифр 19,7%, 43% повторяемости, 3,59% у GPT-4 Turbo и «2,23 млн сэмплов» в аннотации нет. Они известны только из пересказа CSA [В] (а в 04b — «из памяти»). Расхождение «2,23 млн» против «576 000 сэмплов» не объяснено. Возможно, CSA считает по расширенной версии статьи или по другим единицам, но это не проверено. Безопасно цитировать только 5,2% / 21,7%.

**Формат Linux `Assisted-by`.** Текущий docs.kernel.org [П] показывает `Assisted-by: LLM [TOOL1] [TOOL2]`.
