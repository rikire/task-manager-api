# 04. Definition of Done и проверка утверждений

**Статус:** принято 2026-10-05, человек; изменено 2026-10-05 (Stop-хук учитывает фазу TDD, добавлен
статус merged). **Область:** 6 «Проверка».

## Потребность

Агент объявляет «готово», не доведя работу до конца, и неверно сообщает о результате. Нужно, чтобы
«готово» подтверждалось исполняемыми проверками, а приёмка оставалась за человеком.

## Варианты

- **Как подтверждать:** требование в промпте / Stop-хук (хук в конце хода агента, может не дать
  закончить ход), перезапускающий проверки / CI / субагент-верификатор / полный harness
  planner–generator–evaluator.
- **Когда что запускать:** один набор везде / разные наборы по моментам работы.
- **Что считать приёмкой:** факт коммита / явная команда человека.

## Решение

### Проверки по моментам

| Момент | Что запускается | Кто или что запускает |
|---|---|---|
| Цикл TDD | только нужные сейчас тесты | агент |
| После правки файла | форматтер на этом файле | хук PostToolUse |
| Конец хода агента | набор pre-commit или его сокращение (см. «Stop-хук») | Stop-хук, блокирует |
| Перед коммитом | все тесты, форматтер, линтер, тайпчекер; `openspec validate` и проверка ссылок — если менялись спеки или документы | git pre-commit |
| Push / PR | всё из pre-commit + архитектурные правила ([11](11-architecture-design.md)) + мутационное тестирование на изменённых файлах ([06](06-test-quality.md)) + SAST (статический анализ безопасности, [14](14-code-security.md)) + аудит зависимостей | CI, обязательная проверка (required check) |

- `openspec validate` проверяет структуру спек (секции, формат требований и сценариев, дельты), не
  смысл.
- Проверка ссылок в markdown — готовым инструментом (например, `lychee`), не своим скриптом.
- Конкретные инструменты — [32](32-stack-tools.md).
- Pre-commit — ранняя обратная связь: git-хуки не ставятся при клонировании и обходятся
  `--no-verify`. Настоящий гейт — CI. Установка git-хуков — в bootstrap ([29](29-environment.md)).

### Stop-хук

- Запускается, **только если в этом ходе менялись файлы** — разговорные ходы не проверяются.
- Запускает **полный набор pre-commit**, пока он укладывается примерно в минуту; если перерастёт —
  затронутые тесты и линтер по изменённым файлам. Порог проверяется замером.
- **Учитывает фазу TDD** ([05](05-tdd.md)): в фазе `tests` допускаются падения только новых и
  изменённых тестов активного изменения; всё остальное должно быть зелёным. В фазах `impl` и
  `refactor` всё должно быть зелёным.
- Если агент упёрся в стоп-триггер ([13](13-authority.md)) и не может сделать зелёным, срабатывает
  защита от зацикливания ([16](16-guardrails-harness.md)): после нескольких блокировок подряд хук
  отпускает ход, а агент пишет в сводке, что остановился с красным и почему.
- Пишется **fail-closed**: любая внутренняя ошибка хука — exit 2. В Claude Code блокирует только
  exit 2; exit 1 действие пропускает.

### Статусы

| Статус | Что значит | Кто ставит | След |
|---|---|---|---|
| **done** | агент считает задачу сделанной | агент | галочка в `tasks.md` изменения OpenSpec |
| **verified** | локальные проверки зелёные: набор pre-commit прошёл в Stop-хуке | автоматически | вывод проверок в сводке для ревью |
| **accepted** | человек прочитал дифф, прогнал основной сценарий, понимает код | только человек | коммит, сделанный по явной просьбе человека |
| **merged** | CI зелёный, изменение в основной ветке | автоматически | слияние PR ([28](28-hosting-ci-git.md)) |

- Агент коммитит и пушит **только по явной просьбе человека в текущем ходе**; коммит — на группу задач
  ([05](05-tdd.md)), каждая группа принимается отдельно.
- `ask` на `git commit` и `git push`: каждый коммит и пуш подтверждается человеком в запросе
  Claude Code ([13](13-authority.md)).
- `deny` на `--no-verify`: pre-commit работает и при коммите агентом.
- Если CI красный после приёмки, исправление — новое изменение или доработка того же PR.

### Доказательства и сводка для ревью

- Агент прикладывает вывод команд, а не пишет «готово».
- Закончив изменение, агент выдаёт **сводку для ревью**; её состав —
  [18 §1](18-human-comprehension.md).

### Верификатор

Субагент в свежем контексте, который по спеке и диффу пытается опровергнуть «готово». Вердикт
вероятностный, поэтому **в DoD не входит и не блокирует**: агент предлагает его в сводке для
нетривиальных изменений; в CI пока не запускается — только локально ([28](28-hosting-ci-git.md)). Механизм —
[27](27-subagents.md).

## Обоснование

- «Claude stops when the work looks done. Without a check it can run, "looks done" is the only signal
  available»; лестница: промпт → Stop-хук → CI → верификатор (вендор)
  ([ч.5 «Проверка утверждений агента»](research/report/05-architecture-testing-verification.md)).
- Минимальный вариант с гарантией для малого проекта — DoD из команд, Stop-хук, тот же набор в CI;
  полный planner–generator–evaluator в вендорском кейсе в 20+ раз дороже
  ([ч.5](research/report/05-architecture-testing-verification.md)).
- Блокирует только exit 2; exit 1 и таймаут PreToolUse не блокируют; git-хуки обходятся
  ([ч.7 §1](research/report/07-guardrails-harness-process.md)).
- Разделение статусов и риск «механического да» при приёмке
  ([ч.5 «Три состояния»](research/report/05-architecture-testing-verification.md)).
- Ревью в свежем контексте лучше самопроверки, но абсолютный F1 ≈ 28,6%; ревьюеры, которых просят
  искать пробелы, склонны к ложным срабатываниям ([ч.3 п.12](research/report/03-weaknesses.md)).

## Гарантия

- Stop-хук и CI — **Г** (запуск и блокировка); CI с защитой ветки — последний рубеж.
- Pre-commit — **Г** с оговоркой: обходится `--no-verify` (закрыто `deny`), не ставится при
  клонировании (ставит bootstrap).
- `ask` на commit / push — промпт **Г**, решение **Ч**; `deny` на `--no-verify` — **Г** для
  распознаваемых форм команды (вызов через скрипт или нестандартную форму может не совпасть с
  шаблоном; это закрывает песочница — [15](15-agent-security.md)).
- Приложенный вывод команд, сводка для ревью — **Д**.
- Верификатор — **В**.
- Приёмка — **Ч**; риск — приёмка без чтения диффа.
