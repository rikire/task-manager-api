# 28. Хостинг, CI-платформа, git-процесс

**Статус:** принято 2026-10-06, человек. **Области:** 5 «Ограничения», 2 «Планирование и трекинг».

## Потребность

CI — последний рубеж ограждений: его агент не может отключить локально. Но гейтом он становится,
только если в основную ветку нельзя попасть в обход проверок. Нужно выбрать хостинг и CI, устроить
ветки и слияние так, чтобы человеку не приходилось делать лишних действий, и решить, какие проверки
идут в CI.

## Варианты

- **Хостинг и CI:** GitHub + GitHub Actions / GitLab + GitLab CI.
- **Ветки:** работа прямо в основной ветке (CI обнаруживает красное после пуша) / ветка на изменение
  + PR (CI не пускает красное в основную ветку).
- **Слияние:** merge-коммит / squash / rebase.
- **Проверки с LLM в CI** (верификатор, `/security-review`): сразу (нужен ключ API в секретах, каждый
  прогон стоит денег) / пока только локально.

## Решение

1. **GitHub и GitHub Actions.** `gh` уже авторизован; у Claude Code есть интеграция с GitHub
   Actions. Если требования задачи скажут иное — [31](31-task-requirements.md).
2. **Ветки и слияние:**
   - одно изменение OpenSpec — одна ветка (`change/<имя-изменения>`); **активное изменение** — то, по
     имени которого названа текущая ветка;
   - работа вне изменения OpenSpec (рефакторинг, обновление зависимости без смены поведения,
     [07 §5](07-requirements-intent.md)) — ветка `chore/<slug>`;
   - по просьбе человека («запушь», «открой PR») агент пушит (подтверждение `ask`,
     [13](13-authority.md)), открывает PR и включает автослияние;
   - PR вливается сам, когда обязательные проверки зелёные — это статус merged
     ([04](04-definition-of-done.md));
   - способ слияния — **rebase**: история линейная, коммит изменения и коммит инструкций
     ([21](21-attribution.md)) не склеиваются.
3. **Защита `main`:** слияние только через PR; обязательные проверки (§4); запрет обхода, в том числе
   для администраторов; запрет force-push; линейная история. Для приватного репозитория доступность
   защиты веток на бесплатном тарифе не проверена — проверить, если репозиторий будет приватным.
4. **Обязательные CI-джобы** (целевой набор; порядок внедрения — [34](34-core-vs-roadmap.md)):
   - набор push / PR из [04](04-definition-of-done.md): тесты, линтеры, тайпчекер, архитектурные
     правила, мутации на изменённых файлах, SAST, аудит зависимостей;
   - проверки документов ([23](23-documentation.md) §8), связь роадмап ↔ изменения
     ([24](24-planning-tracking.md)), формат коммитов ([25](25-work-history.md)), сканер секретов
     ([14](14-code-security.md)), запрет смешивать инструкции и код в одном коммите
     ([21](21-attribution.md));
   - тесты хуков ([16](16-guardrails-harness.md));
   - **«чистый клон»** — команды «Быстрого старта» README (`docker compose up -d` и проверка API,
     [33](33-readme.md)), затем `make setup` и полный набор проверок ([29](29-environment.md)).
5. **Проверки с LLM — пока только локально:** агент предлагает верификатор
   ([04](04-definition-of-done.md)) и `/security-review` ([14](14-code-security.md)) в сводке для ревью;
   в CI не запускаются. Добавляются в CI, если локальных окажется мало.

## Обоснование

- CI с защитой ветки и обязательными проверками — гарантия, которую агент не отключит локально; без
  защиты ветки CI обходится; у владельца есть право обхода, если не запретить его и
  администраторам ([ч.7 §1](research/report/07-guardrails-harness-process.md)).
- История как артефакт: линейная, без склеивания коммитов
  ([ч.7 §8](research/report/07-guardrails-harness-process.md)).
- LLM-проверки локально, а не в CI, — решение человека: меньше секретов и затрат при почти том же
  результате (пятый принцип, [01](01-process-frame.md)).

## Гарантия

- Защита `main` и обязательные проверки — **Г** (исполняет GitHub).
- Пуш и открытие PR агентом — промпт **Г**, решение **Ч**.
- Предложение LLM-проверок локально — **Д**; их вердикт — **В**.

## Где будет реализовано

- Репозиторий на GitHub, настройки защиты `main` (rulesets / branch protection), автослияние.
- `.github/workflows/` — обязательные джобы из §4.
- AGENTS.md — ветка на изменение, PR с автослиянием по просьбе человека.
