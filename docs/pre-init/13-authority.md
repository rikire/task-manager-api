# 13. Полномочия человека и агента

**Статус:** принято 2026-10-05, человек. **Область:** 5 «Ограничения».

## Потребность

Агент молча принимает решения, которые принадлежат человеку, обходит проверки, соглашается из
вежливости и продолжает работу на опровергнутой гипотезе. При этом если подтверждать каждое действие,
подтверждение превращается в механическое «да». Нужны явная граница решений, наблюдаемые
стоп-триггеры, правила честности и короткий список механических запретов.

## Варианты

- Уровни автономии как проектное решение (Feng et al.): оператор (человек делает сам) → соавтор →
  консультант → утверждающий (агент делает, человек утверждает) → наблюдатель (агент действует
  сам).
- Правила «стоп и спроси» в инструкциях (договорённость).
- Запреты и подтверждения (`deny` / `ask`) в правах Claude Code на дорогие действия; песочница ОС.
- Режимы Claude Code: Manual (подтверждение почти всего — размывается усталостью), auto (действия
  проверяет классификатор — вероятностно), bypass (без подтверждений).

## Решение

**Уровень автономии:** для решений из списка «решает только человек» — «утверждающий»: агент
предлагает и делает, человек решает и подтверждает. Для остального — «наблюдатель»: агент действует
сам и сообщает.

### 1. Граница решений

**Решает только человек:**
- наблюдаемое поведение и контракт: требования, приоритеты, коды и формат ошибок;
- схема данных и миграции;
- новая зависимость;
- всё, что проходит чек-лист значимости ([11](11-architecture-design.md)), и ADR ([12](12-adr.md));
- новая семантика отказов: кэш, повторы, таймауты, асинхронность;
- безопасность: авторизация, секреты, доверие к вводу;
- ослабление или удаление теста или проверки, изменение порогов;
- изменения инструкций агента, harness и процесса;
- приёмка работы: коммит, push.

**Агент решает сам и сообщает одной строкой:** имена, внутренняя структура в рамках принятого
дизайна, приватные вспомогательные функции, раскладка тестов, выбор между равноценными реализациями
за одним интерфейсом. Спрашивать об этом — тоже сбой: подтверждения обесцениваются.

### 2. Стоп-триггеры

Агент прекращает работу, которая зависит от проблемного места, если:
1. проверка опровергла гипотезу, на которой он действовал;
2. начинается вторая попытка того же без новой информации;
3. правка вышла за рамки текущего изменения OpenSpec и его `tasks.md`;
4. результат противоречит спеке, ADR или правилу `C-`;
5. нужное поведение неизвестно и не выясняется;
6. правку нельзя связать с требованием или задачей;
7. тест кажется неверным ([05](05-tdd.md));
8. он не различает, что согласовано, а что только предложено.

При остановке: разделить подтверждённое, опровергнутое и неизвестное; задать **один** конкретный
вопрос с вариантами и рекомендацией.

### 3. Правила честности

- Возразить один раз, с аргументом и альтернативой; после решения выполнить его полностью.
- Называть более простое решение, даже если просили сложное.
- Не скрывать непонимание.
- Отделять факт, интерпретацию и допущение.
- «Не проверено» вместо правдоподобной догадки.

### 4. Механические правила (`.claude/settings.json`)

| Действие | Правило |
|---|---|
| `git commit`, `git push` | ask ([04](04-definition-of-done.md)) |
| `--no-verify` | deny ([04](04-definition-of-done.md)) |
| правка манифестов зависимостей, команды установки пакетов | ask |
| правка миграций | ask |
| правка инструкций (AGENTS.md, CLAUDE.md, `.claude/**`, `.agents/skills/**`, `openspec/config.yaml`) | ask; агент предлагает дифф, коммит отдельный |
| правка конфигурации проверок: `.github/workflows/`, `.githooks/`, `Makefile`, `mise.toml`, конфиги инструментов из [32](32-stack-tools.md) (`phpunit.xml.dist`, `phpstan.neon`, `psalm.xml`, `deptrac.yaml`, `infection.json5`, `.php-cs-fixer.dist.php`) | ask ([06](06-test-quality.md)) |
| `docker compose exec` / `docker compose run` вне целей `make` | ask ([15 §1а](15-agent-security.md)) |
| генерируемые файлы (матрица трассировки, индекс ADR) | deny ([09](09-traceability.md), [12](12-adr.md)) |
| тестовые пути в фазах `impl` и `refactor` | блокирует хук ([05](05-tdd.md), [16](16-guardrails-harness.md)) |
| файл фазы TDD | deny ([16](16-guardrails-harness.md)) |

Обход через скрипт или другую форму команды закрывает песочница ([15](15-agent-security.md)). Всё
остальное разрешено без вопросов, чтобы подтверждения оставались осмысленными.

### 5. Режим прав

- Проект совместим с **auto mode**: явные `ask` и `deny` срабатывают и в нём (проверено по
  документации Claude Code, страница permissions). Рутина проходит через классификатор auto mode
  (**В**), список выше — через человека (промпт **Г**, решение **Ч**).
- Режим в настройках проекта не задаётся — это выбор пользователя.
- `bypassPermissions` запрещён в настройках проекта (`disableBypassPermissionsMode`).

## Обоснование

- Уровень автономии — проектное решение, отдельное от возможностей модели (Feng et al.)
  ([ч.5 «Принятие решений»](research/report/05-architecture-testing-verification.md)).
- Правила проверяются в порядке deny → ask → allow и срабатывают на подкоманды; запрет правки
  встроенным инструментом обходится скриптом без песочницы; «After the tenth approval you're clicking
  through rather than reviewing» (вендор)
  ([ч.5](research/report/05-architecture-testing-verification.md)).
- «An ask rule … still prompts you … even in auto mode» —
  [code.claude.com/docs/en/permissions](https://code.claude.com/docs/en/permissions), проверено
  2026-10-05.
- Обход проверок — слабость с сильной доказательной базой; сикофантия (согласие из вежливости)
  подтверждена вне кода, механической защиты от неё нет ([ч.3 п.14–15](research/report/03-weaknesses.md)).
- Стоп-триггеры и правила честности — по опыту предыдущего проекта автора (Exchange Student Guide
  Platform; файлы `stop-and-ask.md`, `collaboration.md` там, не в этом репозитории).

## Гарантия

- `ask` — промпт **Г**, решение **Ч**; `deny` и запрет bypass — **Г** для распознаваемых форм, с
  песочницей — и для скриптов.
- Классификатор auto mode — **В**.
- Граница решений, стоп-триггеры, правила честности — **Д**; подстраховка — независимый ревьюер
  (**В**) и человек (**Ч**).

## Где будет реализовано

- `.claude/settings.json`: `permissions.ask`, `permissions.deny`, `disableBypassPermissionsMode`.
- AGENTS.md: граница решений, стоп-триггеры, правила честности (с `Source:` на этот документ).
- Пути манифестов, миграций, тестов, конфигов — по стеку.
