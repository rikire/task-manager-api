# 16. Ограждения и проверка harness

**Статус:** принято 2026-10-05, человек; изменено 2026-10-05: файлы состояния вынесены из `.claude/`
в `.agent-state/`. **Набор хуков открыт:** перепроверяется в вопросе №31 «Финальная сверка»
[очереди](to-be-discussed.md). **Область:** 5 «Ограничения».

## Потребность

Harness — всё, что исполняет Claude Code вне модели: хуки, права, песочница. Вместе с CI это даёт
гарантии, только если ограждения загружены, не падают и не обходятся, а у каждого ограждения есть
документированный способ тихо выключиться. Нужно определить набор хуков, переключатель фаз TDD,
который агент не может открыть сам, и способ проверять, что ограждения действительно работают.

## Варианты

- Хуки по событиям: перед действием (PreToolUse, может блокировать), после действия (PostToolUse, не
  блокирует), в конце хода (Stop, может не дать закончить), в начале сессии (SessionStart), при
  сообщении человека (UserPromptSubmit, вставляет контекст).
- Проверка harness: unit-тесты хуков на записанных событиях, список обходов, `/hooks` (просмотр
  загруженных хуков), сквозной прогон `claude -p`.
- Защита ограждений от агента: подтверждение записи в `.claude/` (Claude Code требует его во всех
  режимах, кроме bypass) + `ask` / managed settings — системный файл настроек в `/etc`, который агент
  не может изменить.

## Решение

### 1. Набор хуков (текущий)

| Хук | Событие | Что делает | Откуда |
|---|---|---|---|
| проверка «готово» | Stop | если в ходе менялись файлы — набор pre-commit с учётом фазы TDD; красное → exit 2 | [04](04-definition-of-done.md) |
| проверка сводки | внутри Stop | в последнем ответе есть «Упрощения / Долг / Не сделано» и блок зрелости; реализуемость — при инициализации, до тех пор договорённость | [10](10-debt-polish-headroom.md) |
| защита тестов | PreToolUse Edit/Write | в фазах `impl` и `refactor` блокирует правку тестовых путей | [05](05-tdd.md) |
| гейт намерения | PreToolUse Edit/Write кода и тестов | блокирует, пока в активном изменении есть неразрешённые допущения или открытые вопросы | [07](07-requirements-intent.md) |
| напоминания по действию | PreToolUse с `additionalContext` | при правке манифеста зависимостей, миграций, спек, `*.md` подставляет нужное правило | [03](03-agent-instructions.md), [19](19-agent-writing.md) |
| форматтер | PostToolUse Edit/Write | форматирует файл, не блокирует; если через `docker compose exec` медленно — переносится в Stop | [04](04-definition-of-done.md), [32](32-stack-tools.md) |
| линтер по файлу | PostToolUse Edit/Write | быстрый линтер; замечания возвращаются агенту (exit 2 не блокирует, но передаёт текст) | [26](26-code-quality.md) |
| напоминание о catch и значениях по умолчанию | PostToolUse Edit/Write | при новом catch или значении по умолчанию просит обосновать или убрать | [26](26-code-quality.md) |
| проверка здоровья | SessionStart | хуки загружены, песочница работает, git-хуки установлены, версии инструментов верные; если нет — предупреждение первой строкой в контексте агента, агент сообщает человеку | этот документ |
| сводка состояния | SessionStart (`startup`, `resume`, `compact`) | вставляет сводку состояния и заметки | [17](17-session-state.md) |
| ручные правки человека | — | не делаем, пока агент не затрёт ручную правку | [21](21-attribution.md) |
| git-хуки | pre-commit, commit-msg | набор pre-commit, `openspec validate`, gitleaks, TODO → реестр, запрет маркера `DEBUG:`, запрет смешивать инструкции и код, предупреждение о размере диффа, проверка frontmatter скиллов; commit-msg: commitlint, `Refs:`, `Assisted-by` | [04](04-definition-of-done.md), [09](09-traceability.md), [10](10-debt-polish-headroom.md), [14](14-code-security.md), [18](18-human-comprehension.md), [20](20-skills.md), [21](21-attribution.md), [25](25-work-history.md), [30](30-code-comments.md) |

### 2. Переключатель фаз TDD

- Фаза хранится в `.agent-state/phase` (каталог в `.gitignore`); хук защиты тестов читает этот файл.
- Переключает скрипт `scripts/phase tests|impl|refactor`:
  - **заблокировать тесты** (`impl`, `refactor`) — агент запускает сам, без подтверждения;
  - **разблокировать тесты** (`tests`) — команда под `ask`: агент запускает, человек подтверждает
    одним кликом.
- Прямая запись в файл фазы агенту запрещена: `deny` на правку встроенными инструментами и хук на
  Bash-команды, которые пишут в этот файл (кроме `scripts/phase`). Запрета записи в песочнице для
  файла нет: иначе сам `scripts/phase`, запущенный агентом, не смог бы его записать. Для Bash защита —
  по известным формам команд, обходы — в списке §4.

### 3. Как пишутся хуки

- **Fail-closed:** любая внутренняя ошибка — exit 2 (`set -euo pipefail` + trap). В Claude Code
  блокирует только exit 2.
- **Таймаут:** если хук PreToolUse не укладывается в таймаут, Claude Code выполняет действие
  (fail-open). Поэтому хук обязан быть быстрым сам; в PreToolUse — без сетевых вызовов.
- В выводе — только JSON, без отладочного вывода: лишний текст ломает разбор решения.
- **Защита Stop-хука от зацикливания:** после нескольких блокировок подряд он отпускает ход, а агент
  в сводке пишет, что остановился с красным и почему. Механизм по полям входа хука — проверить при
  реализации.

### 4. Как проверяется harness

- Входные события записываются из реальной сессии текущей версии Claude Code и хранятся как фикстуры;
  unit-тесты хуков на них — в CI.
- Для каждого `deny` и хука — список обходов с пометкой «блокируется» или «не покрыто, держит
  песочница / CI».
- Проверка здоровья на SessionStart; сквозной прогон при онбординге.
- После обновления Claude Code фикстуры перезаписываются — в рамках аудита процесса
  ([22 §4](22-process-learning.md)), по требованию или предложению агента.

### 5. Защита ограждений от агента

Запись в `.claude/` требует подтверждения во всех режимах, кроме bypass; bypass запрещён
([13](13-authority.md)). Поэтому файлы, которые агент пишет часто (заметки), лежат вне `.claude/` —
в `.agent-state/`. Managed settings в `/etc` не берём: нужен sudo, и их нет у того, кто клонирует
репозиторий.

### 6. Последний рубеж

CI с защитой ветки и запретом обхода даже для владельца — [28](28-hosting-ci-git.md).

## Обоснование

- Документированные способы тихо выключить ограждение: exit 1, таймаут PreToolUse, запуск `claude`
  из поддиректории, git-хуки не ставятся при клонировании, обход правила для Bash другой формой
  команды ([ч.7 §1](research/report/07-guardrails-harness-process.md)).
- Хук — код: фикстуры с реальной сессии, unit-тесты, список обходов, `/hooks`, сквозной прогон;
  «ограждение, обход которого нельзя проверить, — договорённость»
  ([ч.7 §2](research/report/07-guardrails-harness-process.md)).
- Для малого проекта окупаются 2–4 fail-closed хука, их тесты и CI с защитой ветки
  ([ч.7 §1](research/report/07-guardrails-harness-process.md)).

## Гарантия

- Блокирующие хуки — **Г**, если загружены и протестированы; проверка здоровья делает отключение
  заметным.
- Переключатель фаз: блокировка тестов — без подтверждения; разблокировка — промпт **Г**, решение
  **Ч**; прямая запись — **Г** для встроенных инструментов, для Bash — по известным формам команд.
- Проверка сводки — **Гф**, если надёжно реализуема; иначе **Д**.
- Напоминания — **Г доставки**.

## Где будет реализовано

- `.claude/settings.json` — хуки, `ask` на `scripts/phase tests`, `deny` на `.agent-state/phase`.
- `.claude/hooks/` — скрипты хуков; `tests/hooks/fixtures/` — записанные события.
- `scripts/phase`; `.agent-state/` в `.gitignore`.
- Git-хуки — ставит bootstrap.
