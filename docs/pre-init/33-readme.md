# 33. Главный README проекта

**Статус:** принято 2026-10-06, человек. **Область:** 4 «Контекст и инструкции».

## Потребность

Корневой README — первое, что открывает проверяющий. Он должен быстро поднять проект и проверить API,
увидеть архитектурные решения и то, как использовался ИИ (этого требует задача,
[31](31-task-requirements.md)), а владельцу — служить обзором репозитория со ссылками на артефакты и
коротким гайдом по разработке. Агент README почти не читает: у него AGENTS.md и `docs/README.md`
([23](23-documentation.md)).

## Варианты

- Порядок разделов: сначала путь проверяющего / сначала обзор репозитория.
- Содержание: обзор и ссылки / подробности в самом README.
- Время работы: замер / оценка по истории / не указывать (задача требует честную цифру).

## Решение

### 1. Структура

```
# <Название> — <одна строка: что это>

Короткий абзац: что за сервис, что умеет, статус (тестовое задание; коммит сдачи — при сдаче).

## Быстрый старт                         ← требование задачи
- Нужно: Docker (+ Compose).
- git clone … && cd …
- docker compose up -d                    (миграции применяются при старте)
- адрес API и документации (/api/doc)
- 2–3 примера curl; полный набор — в отдельном файле

## Архитектурные решения и компромиссы   ← требование задачи, 3–7 пунктов
- решение + почему + ссылка на ADR; обязательно: связь Task и Status, удаление статуса
  с задачами, структура проекта, что сознательно упрощено

## Использование ИИ                       ← требование задачи
- как устроена работа: агент пишет код, человек решает и принимает
- как проверялся результат: TDD, проверки, CI, ревью, explain-back
- ссылки: процесс — docs/pre-init/ и AGENTS.md (docs/process/ — когда появится), трейлер Assisted-by

## Что дальше                             ← требование задачи
- 3–7 пунктов из роадмапа (что не сделано) и реестра улучшений (что можно лучше)

## Сколько времени ушло                   ← требование задачи
- оценка, отдельно на проектирование процесса и на продукт; с пометкой, как получена

## Как устроен репозиторий
- карта: docs/README.md, роадмап, архитектура, ADR, спеки OpenSpec, процесс, pre-init

## Разработка
- предустановки: git, Docker, Claude Code, gh, mise, make, bubblewrap
- make setup → первый запуск claude (подтвердить доверие к папке)
- таблица команд make
- процесс в пять шагов: изменение OpenSpec → тесты → реализация → проверки → приёмка и PR
```

### 2. Правила

- **Только обзор и ссылки:** подробности живут в своих документах ([19](19-agent-writing.md), «один
  факт — одно место»); архитектурные пункты — краткие формулировки со ссылкой на ADR.
- **На русском** ([23](23-documentation.md)).
- **Примеры curl** — в отдельном файле; в README — 2–3.
- **Команды «Быстрого старта» выполняет CI** в джобе «чистый клон» ([28](28-hosting-ci-git.md),
  [29](29-environment.md)): если README врёт, CI красный.
- **Время** не замеряется; перед сдачей оценивается по истории git (даты коммитов) и датам работы, в
  README указано, что это оценка и как она получена.
- **Когда пишется:** при инициализации — скелет; полный текст — в конце работы над продуктом, со
  скиллом `doc-coauthoring` и проверкой читателем ([19](19-agent-writing.md)).

Предварительная структура в [29 §7](29-environment.md) заменяется этой.

## Обоснование

- Разделы «Как запустить», «Архитектурные решения и компромиссы (3–7)», «Что дальше», «Использование
  ИИ», «Сколько времени ушло» и примеры curl требует задача; проект должен подниматься по README одной-
  двумя командами ([31](31-task-requirements.md)).
- Порядок, правила и оценка времени — решения человека.

## Гарантия

- Команды «Быстрого старта» — **Г** (CI, «чистый клон»); ссылки — **Гф** ([23](23-documentation.md)).
- Содержание и честность разделов — **Д**; проверка читателем — **В**; итог — **Ч**.

## Где будет реализовано

- `README.md` — скелет при инициализации, полный текст в конце.
- Файл с примерами curl — `docs/api/curl-examples.md` ([23](23-documentation.md)).
- CI — джоб «чистый клон» выполняет команды «Быстрого старта».
