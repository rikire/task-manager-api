# 12. ADR

**Статус:** принято 2026-10-05, человек. **Область:** 3 «Архитектура и решения».

## Потребность

ADR (Architecture Decision Record) — короткая запись одного архитектурного решения с причинами и
компромиссами. Без таких записей решения расходятся между сессиями агента, агент «чинит» осознанные
компромиссы, а причины решений теряются. Нужна запись дорогих решений, которую агент находит и на
которую опираются правила и код.

## Варианты

- **Формат:** Nygard (контекст / решение / последствия) / Y-statement (одна фраза «в контексте … ради
  … решили … принимая …») / MADR (Markdown Architectural Decision Records: полный или минимальный
  шаблон).
- **Когда:** на каждое решение / только на дорогие.
- **Кто пишет:** агент черновик, человек принимает / человек пишет Y-statement, агент дополняет /
  журнал решений агента со статусом «предложено».
- **Статусы:** proposed / accepted / superseded / deprecated — или упрощённый набор.

## Решение

### 1. Когда писать

- Изменение прошло чек-лист значимости ([11 §2Б](11-architecture-design.md)): новый модуль или
  граница; схема данных; контракт API; новая зависимость, которую трудно заменить; новая сквозная
  концепция; влияние на сценарий качества `QAS-`; трудно откатить.
- Отступление от действующего ADR, ограничения `CON-` или правила `RUL-`.
- **Стек:** язык, фреймворк, БД, способ развёртывания — ADR на каждое.
- **Библиотеки:** ADR, если библиотека расползается по коду или задаёт архитектуру (ORM,
  HTTP-фреймворк, валидация, авторизация, очереди). Мелкая заменяемая утилита — без ADR: строка в
  секции «Известные решения» `design.md` ([07 §4](07-requirements-intent.md),
  [11](11-architecture-design.md)) и одобрение зависимости человеком ([13](13-authority.md)).
- Сводная таблица стека — в `docs/architecture/README.md`, секция «Стратегия решения»: технология →
  зачем → ADR (если есть). Таблица перечисляет, решения живут в ADR.

### 2. Формат

Минимальный MADR + поля проекта:

- **Status:** `active` / `deprecated`; **Replaced by:** `ADR-…` (если решение заменено); дата.
- **Kind:** `architecture` / `process` (изменения процесса после заморозки pre-init,
  [23 §4](23-documentation.md)).
- **Decided by:** владелец проекта; **Drafted by:** агент.
- **Context and drivers:** для `architecture` — ссылки на требования `REQ-`, сценарии качества `QAS-`,
  ограничения `CON-`; для `process` — на записи журнала сбоев `FAIL-`, долга `DEBT-` или документ
  решения.
- **Considered options:** минимум 2.
- **Trade-offs:** таблица «варианты × атрибуты качества»; точки компромисса и чувствительности
  ([11](11-architecture-design.md)).
- **Decision and rationale** — единственный нормативный раздел ([08](08-normative-descriptive.md)):
  что решено и почему, со ссылкой на применённый паттерн, тактику или принцип.
- **Consequences:** плюсы и минусы.
- **Confirmation:** как проверяется соблюдение — метка теста или ID правила зависимостей, если
  проверяемо машиной (CI проверяет, что они существуют и проходят); иначе «review».
- **Retires:** точные формулировки или ID правил (`RUL-…`), которые решение отменяет; CI ищет их по
  репозиторию. Пример: `Retires: RUL-ARCH-repository-per-entity; "each entity has its own repository"`.
- **Revisit-when:** при каком условии пересмотреть.

Язык ADR — английский: ADR живут в проекте и читаются агентом ([03](03-agent-instructions.md) п. 9).
Документы решений в `docs/pre-init/` — замороженная история для людей, поэтому на русском. Язык
остальных документов — [23](23-documentation.md).

### 3. Принятие

Черновик ADR пишет агент (скилл `architecture`) внутри изменения; до коммита он лежит в рабочей
копии незакоммиченным. **Принятие — коммит с ADR, подтверждённый человеком** ([04](04-definition-of-done.md)).
Чтобы это не слилось с рутинным подтверждением коммита, агент в запросе на коммит явно пишет «этот
коммит принимает ADR-NNNN-<slug>». Статуса «proposed» нет.

### 4. Жизненный цикл

Мелкие правки (опечатки, ссылки, форматирование) допустимы. Изменение решения — только новым ADR;
старый получает `deprecated` и `Replaced by:` (вместо отдельного статуса «superseded»).

### 5. Как агент узнаёт об ADR и трассируемость

- Строка в карте AGENTS.md: «перед изменением структуры, контракта, схемы или зависимостей →
  `docs/adr/`».
- **Индекс ADR** (`docs/adr/README.md`: номер, слаг, статус, суть в одну строку) — генерируется
  скриптом.
- Ссылки на ADR там, где уместно: `Source:` правил `RUL-ARCH-…`; `design.md` (`ADR: ...`);
  комментарии в коде в местах реализации решения ([30](30-code-comments.md)); описание
  архитектуры.

### 6. Проверки

- Confirmation с тестом — в CI.
- `Retires:` — CI ищет отменённые формулировки.
- Форма ADR: обязательные поля, минимум 2 варианта, ссылки на драйверы.
- Индекс ADR актуален.
- Упомянутый ADR существует; ссылка на `deprecated` ADR — предупреждение, а из раздела архитектурных
  решений README — ошибка (решение человека 2026-10-06, сценарий `QAS-MAINT-readme-matches-code`).

## Обоснование

- Форматы стабильны (Nygard, Y-statement, MADR); в MADR есть Confirmation — «how compliance is
  validated»; для малого проекта — минимальный MADR и только дорогие решения; агент пишет черновик,
  человек принимает ([ч.5 «ADR»](research/report/05-architecture-testing-verification.md)).
- ADR как контекст для агента: указатель в инструкциях, тексты — по требованию; гарантию даёт только
  Confirmation-проверка ([ч.5](research/report/05-architecture-testing-verification.md)).
- Отменённые формулировки остаются в других документах — отсюда `Retires:` и поиск остатков
  ([ч.6 «Согласованность инструкций»](research/report/06-context-security-docs.md)).
- Упрощение статусов — решение человека: черновик не попадает в репозиторий до подтверждённого
  коммита, поэтому «proposed» и отдельный шаг «accepted» не нужны.

## Гарантия

- Confirmation с тестом — **Г**.
- Форма ADR, `Retires:`, индекс, существование ссылок — **Гф**.
- Принятие — промпт коммита **Г**, решение **Ч**.
- Полнота вариантов и честность компромиссов — **Д**, проверяет человек.

## Где будет реализовано

- `docs/adr/ADR-NNNN-<slug>.md`, шаблон ADR, `docs/adr/README.md` (генерируемый индекс).
- Скилл `architecture` — черновик ADR.
- Скрипты проверки (форма, Retires, индекс, ссылки) — в pre-commit и CI.
- Таблица стека — `docs/architecture/README.md`.
