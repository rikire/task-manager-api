# 03. Инструкции агенту

**Статус:** принято 2026-10-05, человек. **Область:** 4 «Контекст и инструкции».

## Потребность

Агент должен знать правила проекта и получать нужное правило в момент, когда оно применимо, не
тратя контекст на то, что он и так выведет из кода. Агент также должен сразу понимать, какие
механизмы и документы в проекте есть и когда к ним обращаться.

## Варианты

- **Основной файл:** AGENTS.md (открытый формат, его читают Claude Code, Codex, Cursor и другие) /
  CLAUDE.md (только Claude Code) / оба с дублированием.
- **Содержание:** полный обзор проекта / только то, что агент не выведет сам.
- **Объём:** жёсткий лимит с проверкой в CI / без лимита, но без воды.
- **Доставка:** всё в одном файле / раскладка по каналам (файл, правила по путям, хуки, скиллы,
  субагенты).
- **Автопамять** (заметки, которые Claude Code сам пишет вне репозитория): включена / выключена.

## Решение

1. **Основной файл — `AGENTS.md`:** правила не привязаны к одному инструменту. `CLAUDE.md` содержит
   строку `@AGENTS.md` (импорт) и только то, что нужно исключительно Claude Code.
2. **В AGENTS.md — только то, чего агент не выведет сам:**
   - команды: bootstrap, тесты, проверка;
   - нестандартные правила и запреты, у каждого — «почему» и `Source:` (ссылка на документ решения,
     ADR или требование; формат — [08](08-normative-descriptive.md));
   - **карта «ситуация → механизм»**: что делать и куда смотреть, когда возникает ситуация. Например:
     нужно архитектурное решение → скилл `architecture` и `docs/adr/` ([11](11-architecture-design.md),
     [12](12-adr.md)); нашёл недоделку → реестр долга ([10](10-debt-polish-headroom.md)); нужна новая
     зависимость → одобрение человеком ([13](13-authority.md)); меняется поведение → изменение OpenSpec
     ([02](02-sdd-framework.md)). Каждая строка ведёт на скилл, команду или документ;
   - сквозные принципы из [01](01-process-frame.md).

   **Не кладём:** обзор структуры кода и стека — агент найдёт это поиском. Карта механизмов — не
   обзор репозитория: она описывает процессы и когда их запускать, а не код.
3. **Жёсткого лимита объёма нет.** Правило — без воды: каждая строка проходит тест «станет ли агент
   ошибаться, если её убрать»; дубли и пересказ кода удаляются.
4. **Раскладка правил по каналам доставки:**

   | Тип правила | Канал | Ограничение |
   |---|---|---|
   | нужно всегда | AGENTS.md | переживает `/compact` |
   | касается области кода | `.claude/rules/*.md` с полем `paths` — подгружается, когда агент читает или правит подходящий файл встроенным инструментом | после `/compact` пропадает до следующего такого чтения; правка файла через Bash, вероятно, правило не подгружает (не проверено) |
   | критично в момент действия | хук PreToolUse: напоминание (поле `additionalContext` вставляет текст в контекст) или блокировка | хук — код, его надо тестировать ([16](16-guardrails-harness.md)) |
   | многошаговая процедура | скилл, вызываемый явно; скилл с побочными эффектами — с `disable-model-invocation` (вызывает только человек) | модель сама вызывает скилл не всегда, поэтому скилл есть в карте AGENTS.md |
   | роль (ревьюер и т.п.) | промпт субагента | общие правила в субагент не попадают |

5. **Кто пишет инструкции:** агент предлагает дифф, человек правит и принимает. Правка инструкций —
   под `ask` ([13](13-authority.md)); отдельные коммиты — [21](21-attribution.md).
6. **Версии, API и флаги проверяются по источнику** (документация, исходники зависимостей, вывод
   команды, поиск в интернете — [15](15-agent-security.md)), а не по памяти. Подкрепляется
   тайпчекером и проверкой пакетов ([26](26-code-quality.md), [15](15-agent-security.md)).
7. **Проверка ссылок в инструкциях:** markdown-ссылки — готовым инструментом (например, `lychee`,
   [04](04-definition-of-done.md)); существование упомянутых путей, скиллов и команд — отдельной
   проверкой в CI (скрипт; в роадмапе — [34](34-core-vs-roadmap.md)).
8. **Автопамять агента в проекте выключена** (`autoMemoryEnabled: false`): правила живут только в
   репозитории и принимаются человеком.
9. **Файлы для агента — на английском**, кроме документов, основной читатель которых — человек
   ([23 §6](23-documentation.md)): агент их тоже читает, но пишутся они по-русски.

## Обоснование

- Файлы инструкций почти не меняют долю решённых задач, но удорожают работу на 20%+; сгенерированные
  моделью хуже написанных человеком; обзоры репозитория бесполезны, нестандартные правила полезны
  (исследование ETH Zurich, arXiv 2602.11988) — [ч.6 «Контекст агента»](research/report/06-context-security-docs.md).
- Сжатый индекс в AGENTS.md сработал в 100% случаев против 53% у скилла, который модель должна
  вызвать сама (эвал Vercel, вендор) — отсюда карта в постоянном контексте
  ([ч.6](research/report/06-context-security-docs.md)).
- Правило, прочитанное в начале сессии, со временем «тонет»; хуки — единственный канал, который
  вставляет текст в момент события; правила по путям пропадают после `/compact`
  ([ч.6 «Доставка инструкции»](research/report/06-context-security-docs.md)).
- Длинный контекст ухудшает следование инструкциям, точного порога нет (бенчмарк IFScale, отчёт
  Chroma о длинном контексте) — поэтому «без воды», а не число строк
  ([ч.6](research/report/06-context-security-docs.md)).
- Автопамять хранится локально, вне репозитория, и пишется самим агентом
  ([ч.7 «Кто может менять инструкции»](research/report/07-guardrails-harness-process.md)).

## Гарантия

- AGENTS.md в контексте на старте и после `/compact` — **Г доставки**; выполнение — **Д**.
- Хук-напоминание — **Г доставки**; хук-блокировка — **Г**.
- Существование упомянутых путей, ссылок, скиллов, команд — **Гф** (CI).
- «Без воды», полнота карты механизмов — **Ч** (ревью человеком).
- Выключенная автопамять — **Г**, если пользовательские настройки её не включают обратно (проверить
  приоритет настроек при инициализации).

## Где будет реализовано

- `AGENTS.md`, `CLAUDE.md` в корне.
- `.claude/rules/*.md` — правила по путям, по мере появления областей кода.
- `.claude/settings.json` — `autoMemoryEnabled: false`, хуки.
- Проверка ссылок и упоминаний — в CI.
- Навигация по документации для агента и человека — [23](23-documentation.md).
