# Pre-init: что продумано до инициализации проекта

Эта папка — след работы, сделанной **до** инициализации репозитория: как устроен процесс разработки,
в которой код в основном пишет ИИ-агент (Claude Code) под руководством человека, какие решения
приняты и почему. Читать её стоит, чтобы понять, откуда в проекте взялись правила, хуки, скиллы и
проверки.

## Статус

**Живая**, пока идут исследование и решения. После инициализации проекта папка **замораживается**:
её больше не правят, вся документация дальше ведётся в самом проекте. Здесь будет отметка коммита
заморозки.

## Принцип

Процесс проектируется **независимо от конкретной задачи**: требования задачи сюда намеренно не
попадают, чтобы не подгонять процесс под неё. Задача была открыта только после того, как процесс спроектирован; что она меняет в процессе —
[31](31-task-requirements.md).

## Порядок работы

1. **Исследование** — бриф в [research/README.md](research/README.md), отчёт —
   [research/report.md](research/report.md).
2. **Решения** — вопросы стоят в очереди [to-be-discussed.md](to-be-discussed.md). Каждый обсуждается с человеком, затем на него пишется документ `NN-<тема>.md`.
   Решение без документа не реализуется.
3. **Инициализация проекта** по принятым решениям, затем заморозка этой папки.

**Номера.** Номер документа — порядок принятия решений, номер вопроса в очереди — порядок
постановки; они могут не совпадать (например, вопрос №32 «Как агент пишет тексты» стал документом
`19-agent-writing.md`). В документах «вопрос №N» всегда означает номер в очереди.

### Как устроен документ решения

- **Шапка:** **Статус** — принято / пробное, дата, кто решил («человек» — владелец проекта,
  единственный разработчик); **Область** — номер области из [01](01-process-frame.md).
- **Потребность** — какую проблему решаем.
- **Варианты** — механизмы с плюсами и минусами.
- **Решение** — что выбрано.
- **Обоснование** — почему, со ссылками на исследование.
- **Гарантия** — что проверяется машиной, а что остаётся договорённостью (классы — ниже).
- **Где будет реализовано** — файлы и механизмы в проекте после инициализации.

Отменённое решение остаётся с пометкой и ссылкой на то, что его заменило; номер не переиспользуется.

## Классы гарантий

Каждый механизм помечен тем, насколько он надёжен (подробно — [01](01-process-frame.md)):

| Класс | Значение |
|---|---|
| **Г** | гарантия: исполняется вне модели (хук, права, песочница, CI) и не зависит от того, послушался ли агент |
| **Г запуска** | гарантировано, что проверка выполнится; не гарантировано, что она поймает всё |
| **Г доставки** | гарантировано, что текст попадёт агенту в контекст; не гарантировано, что агент его выполнит |
| **Гф** | гарантия формы: машина проверяет наличие и структуру, но не смысл |
| **В** | вероятностная проверка: проверяет другая модель (LLM), вердикт может ошибаться |
| **Д** | договорённость: текст, который агент (или человек) может не выполнить |
| **Ч** | суждение человека |

Запрос подтверждения (`ask`) записывается как «промпт — Г, решение — Ч»: машина не пропустит без
ответа, но что ответить, решает человек.

## Глоссарий

- **Агент** — Claude Code; **субагент** — отдельный экземпляр агента со своим контекстом, которого
  агент запускает для подзадачи.
- **Harness** — всё, что исполняет Claude Code вне модели: хуки, права, песочница, настройки.
- **Хук** — скрипт, который Claude Code запускает на событие (перед действием, после действия, в
  конце хода, в начале сессии) и который может заблокировать действие.
- **Права (`allow` / `ask` / `deny`)** — правила Claude Code: разрешить без вопроса / спросить
  человека / запретить.
- **Песочница** — изоляция на уровне ОС для команд, которые агент запускает в shell: ограничивает
  файлы и сеть.
- **Скилл** — файл с инструкцией-процедурой, который агент загружает при вызове (`/имя`).
- **Ход** — один ответ агента на сообщение человека, со всеми его действиями.
- **`/compact`** — сжатие истории разговора, когда контекст переполняется; **`/clear`** — очистка.
- **Изменение OpenSpec** — единица работы: папка `openspec/changes/<имя>/` с proposal, дельтой спеки,
  задачами; проходит propose → apply → archive ([02](02-sdd-framework.md)). Одно изменение — один
  **вертикальный срез** (одно наблюдаемое поведение сквозь все слои). **Активное изменение** — то, по
  имени которого названа текущая ветка `change/<имя>` ([28](28-hosting-ci-git.md)).
- **Сводка для ревью** — отчёт агента в конце работы над изменением ([18](18-human-comprehension.md)).
- **Bootstrap** — подготовка свежего клона к работе: `make setup` ([29](29-environment.md)).
- **Вендор** — производитель инструмента или модели (обычно Anthropic); пометка «(вендор)» у
  источника значит, что данные заинтересованные.
- **[В] / [П] / [И] в цитатах исследования** — вторичный источник / проверено по первоисточнику /
  интерпретация; не путать с классом **В**.
