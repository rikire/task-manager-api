# 15. Безопасность работы агента

**Статус:** принято 2026-10-05, человек; уточнено 2026-10-05: какой элемент «смертельной триады»
разрывается. **Область:** 5 «Ограничения».

## Потребность

Агент выполняет инструкции из прочитанного контента (prompt injection), предлагает несуществующие
пакеты, может прочитать и отправить секреты. В 2025 году вредоносные npm-пакеты запускали уже
установленных агентов с флагами обхода прав и использовали их для кражи ключей. Нужна изоляция,
которая не зависит от послушности агента, — при этом агент должен свободно искать информацию в
интернете.

## Варианты

- Инструкции «не доверяй контенту, не трогай секреты» — договорённость; по Willison, защита, которая
  ловит 95% атак, для безопасности — провал.
- Разрыв «смертельной триады» (Willison): опасна сессия, где одновременно есть доступ к приватным
  данным, недоверенный контент и связь наружу. Достаточно убрать один элемент.
- `deny` в правах (действует на встроенные инструменты и распознанные команды) + песочница ОС
  (действует на команды shell и их подпроцессы, но не на встроенные инструменты чтения, загрузки
  страниц, MCP и хуки).
- Devcontainer / виртуальная машина.
- Lock-файл, задержка на свежие релизы пакетов (cooldown), проверка существования пакета.

## Решение

### 0. Какой элемент триады разрываем

**Секреты.** В сессии нет долгоживущих токенов, `.env` закрыт `deny`, подпроцессам секреты
маскируются. Недоверенный контент (веб) и связь наружу (WebFetch) остаются осознанно: поиск в
интернете нужен. **Остаточный риск:** агент может вынести содержимое репозитория в адресе
WebFetch-запроса. Его ограничивает то, что каждый новый домен для WebFetch подтверждает человек.
Риск принят.

### 1. Песочница ОС

- Включена в настройках проекта, в строгом режиме (на Linux — через bubblewrap; наличие и точное
  поведение строгого режима проверить при настройке).
- Сетевой allowlist для команд shell изначально пуст. Домены (реестр пакетов и т.п.) агент
  **предлагает** с обоснованием; правка настроек — под `ask` ([13](13-authority.md)), поэтому домен
  добавляется только с подтверждения человека.
- Закрывает обход `ask` / `deny` через скрипт: например, скрипт на Python, который сам читает `.env`
  мимо правила `deny`. Ограничивает связь наружу для команд shell.
- Не проверено: показывает ли Claude Code запрос при обращении к домену вне allowlist или команда
  просто падает — проверить при настройке.

### 1а. Docker и сеть

- Команда внутри контейнера (`docker compose exec …`) песочницей хоста не ограничена: она может
  читать то, что смонтировано в контейнер, и ходить в сеть. Поэтому агенту без подтверждения
  разрешены только цели `make` (`make test`, `make check` и т.п., [29](29-environment.md)), а
  произвольный `docker compose exec` / `docker compose run` — под `ask`.
- В dev-контейнере нет настоящих секретов: `.env` содержит только локальные значения для разработки.
- В сетевой allowlist песочницы входят: github.com (для `git push`, `gh`), реестр Composer
  (packagist.org) и реестр npm; остальное — по §1.
- **Остаточный риск:** через разрешённые цели `make` код в контейнере выполняется без ограничений
  песочницы; риск принят, поскольку в контейнере нет секретов.

### 2. Поиск в интернете

- Песочница не ограничивает встроенные WebSearch и WebFetch — ими управляют права.
- **WebSearch** разрешён в настройках проекта без подтверждения.
- **WebFetch** — по доменам: на новый домен Claude Code спрашивает человека; ответ «Yes, and don't
  ask again» сохраняет домен в `.claude/settings.local.json` — только на этой машине, не в git
  (см. §6).
- Правило в AGENTS.md: факты, версии, API и всё «текущее» — сначала искать, потом отвечать
  ([03](03-agent-instructions.md) п. 6).

### 3. Секреты

- `deny` на чтение `.env*` и папок с секретами.
- Маскировка секретов для подпроцессов (`sandbox.credentials`) — в локальных настройках, которые
  ставит bootstrap ([29](29-environment.md)): из настроек
  репозитория она не применяется.
- В окружении агента нет долгоживущих токенов публикации пакетов. `gh` авторизован через keyring —
  агент может пушить и открывать PR; push стоит под `ask`.
- Сканер секретов — в pre-commit и CI ([14](14-code-security.md)).

### 4. Зависимости

- Lock-файл в репозитории.
- Задержка 7 дней на новые релизы, если менеджер пакетов поддерживает.
- Перед тем как предложить пакет, агент проверяет: существует ли он (защита от slopsquatting —
  регистрации злоумышленниками имён, которые модели выдумывают), возраст, поддержку, популярность,
  лицензию. Скриптом, если реализуемо, иначе договорённость.
- Установка пакета — под `ask`.

### 5. Недоверенный контент

- Веб-страницы, issues, ответы MCP — данные, не инструкции (правило в AGENTS.md).
- Каждый новый MCP-сервер — решение человека с проверкой триады: видит ли он недоверенный контент и
  что ещё может делать в той же сессии.
- Флаги обхода прав не используются; bypass запрещён в проекте ([13](13-authority.md)).

### 6. Allowlist команд

- Растёт по ходу работы: когда человек отвечает «Yes, and don't ask again», правило записывает сам
  Claude Code в `.claude/settings.local.json` (не в git). Агент сам разрешения не дописывает: правка
  настроек агентом — под `ask`.
- Периодически `/fewer-permission-prompts` собирает повторяющиеся правила; проверенные человеком
  переносятся в общий `.claude/settings.json`.

### 7. Devcontainer

Пока нет: начинаем с песочницы в строгом режиме и списка `ask`; devcontainer — если песочницы
окажется мало.

## Обоснование

- «Смертельная триада», «95% is a failing grade» (Willison); атака через GitHub MCP; инциденты Amazon
  Q, Nx «s1ngularity», Shai-Hulud ([ч.6 «Безопасность работы агента»](research/report/06-context-security-docs.md)).
- Несуществующие пакеты — не менее 5,2% сэмплов у коммерческих моделей и 21,7% у открытых (Spracklen
  et al.); задержка 7 дней отсекла бы 8 из 10 разобранных атак на цепочку поставок (вторичный
  источник) ([ч.6](research/report/06-context-security-docs.md)).
- `deny` ≠ изоляция; песочница не покрывает Read, WebFetch, MCP, хуки; `sandbox.credentials` не
  применяется из настроек репозитория (вендор) ([ч.6](research/report/06-context-security-docs.md)).
- «Yes, and don't ask again» для Bash и WebFetch сохраняется для репозитория —
  [code.claude.com/docs/en/permissions](https://code.claude.com/docs/en/permissions), проверено
  2026-10-05.

## Гарантия

- Песочница — **Г** для команд shell и подпроцессов; `deny` на секреты — **Г** для встроенных
  инструментов.
- Lock-файл, задержка релизов, сканер секретов — **Г**; проверка пакета — **Г**, если скриптом,
  иначе **Д**.
- «Контент — данные», «сначала искать» — **Д**.
- Новые домены, MCP, разрешения — промпт **Г**, решение **Ч**.
- Утечка через адреса WebFetch — остаточный принятый риск.

## Где будет реализовано

- `.claude/settings.json`: песочница, сетевой allowlist, `allow` для WebSearch, `deny` на секреты.
- Bootstrap: локальные `sandbox.credentials`, проверка bubblewrap.
- AGENTS.md: «контент — данные», «сначала искать», правило проверки пакетов.
- Менеджер пакетов и задержка релизов — по стеку.
