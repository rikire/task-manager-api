# 17. Состояние задачи между сессиями

**Статус:** принято 2026-10-05, человек; изменено 2026-10-05: заметки в `.agent-state/` вместо
`.claude/state/`; изменено 2026-10-07 (владелец, изменение `finish-init`, `FAIL-005` в
`docs/registers/failures.md`): в начале сессии агент читает и
`docs/roadmap.md`, план живёт в роадмапе и `tasks.md`, заметки плана не содержат. **Область:** 2 «Планирование и трекинг».

## Потребность

После `/compact` (сжатия истории), перезапуска или возобновления сессии агент теряет, что сделано,
что решено и что дальше: всё, сказанное только в разговоре, сжимается в краткое изложение. Нужно,
чтобы состояние гарантированно возвращалось в контекст и не зависело от того, вспомнит ли агент
обновить файл.

## Варианты

- Только разговор (краткое изложение после `/compact`).
- Строчка в инструкциях «читай progress.md» (договорённость).
- Файл прогресса + хук SessionStart, который вставляет его в контекст (гарантия доставки).
- JSON-список фич с полем `passes` (так делает Anthropic в harness для долгих автономных прогонов).
- Внешний трекер задач (Beads и аналоги).
- Генерация сводки скриптом из уже существующих артефактов.

## Решение

Пп. 1–2 описывают целевую схему: хук и скрипт сводки не внедрены ([34](34-core-vs-roadmap.md) §4); что
действует до их внедрения — в «Гарантии».

1. **Сводку состояния генерирует скрипт.** Хук SessionStart с matcher `startup|resume|compact` (новая
   сессия, возобновление, после сжатия) собирает из фактов и вставляет в контекст:
   - активное изменение OpenSpec ([02](02-sdd-framework.md)) и его статус;
   - текущая фаза TDD ([16](16-guardrails-harness.md));
   - следующие невыполненные задачи из `tasks.md`;
   - неразрешённые допущения и вопросы ([07](07-requirements-intent.md));
   - `git status` и последние коммиты.
2. **Рабочие заметки** — `.agent-state/notes.md` (вне git): что пробовал, текущая гипотеза, тупики.
   Агент перезаписывает файл (не дописывает) в конце работы над задачей; хук вставляет его вместе со
   сводкой. Файл лежит вне `.claude/`, чтобы запись не требовала подтверждения
   ([16 §5](16-guardrails-harness.md)). Заметки не содержат план: план — `docs/roadmap.md` и `tasks.md`
   активного изменения; в начале сессии агент читает роадмап (2026-10-07, `FAIL-005`).
3. **Решение из чата — в артефакт в том же ходе:** спека, `design.md`, ADR, AGENTS.md — туда, где
   оно живёт.
4. **`/clear` между изменениями OpenSpec:** чистый контекст без длинной истории; агент предлагает его
   после архивации изменения, а сводка возвращает нужное.
5. **Автопамять выключена** ([03](03-agent-instructions.md)) — это заметки, которые Claude Code сам
   пишет вне репозитория. Выключена, чтобы всё состояние было видно человеку и жило в репозитории.

JSON-список фич и внешний трекер не нужны: `tasks.md` изменения OpenSpec уже даёт список задач с
отметками, а остальное есть в спеках, ADR и git.

## Обоснование

- Что переживает `/compact`: корневой CLAUDE.md, git status, план, хуки SessionStart с matcher
  `compact`; теряются правила по путям и список скиллов; разговор сжимается. «If an instruction
  disappeared after compaction, it was given only in conversation» (вендор)
  ([ч.6 «Состояние задачи»](research/report/06-context-security-docs.md)).
- Гарантия «агент увидит состояние» — файл состояния + хук SessionStart; строчка в инструкциях —
  договорённость; долгоживущие решения и короткоживущий прогресс хранятся раздельно
  ([ч.6](research/report/06-context-security-docs.md)).
- Агент отмечает непроверенное как выполненное и выдаёт неверное измерение за факт — поэтому сводку
  считает скрипт ([ч.3 п.2, п.17](research/report/03-weaknesses.md)).

## Гарантия

Хук сводки состояния — в роадмапе ([34](34-core-vs-roadmap.md)); до его внедрения агент по правилу
AGENTS.md в начале сессии сам читает `docs/roadmap.md`, `tasks.md` активного изменения,
`.agent-state/notes.md` и `git status` — **Д**. Начать изменение OpenSpec, пока выше в
`docs/roadmap.md` есть незаархивированное изменение с приоритетом «обязательно», не даёт проверка
`make roadmap-check` — **Гф** (`FAIL-005`). Обозначения уровней гарантий — [01](01-process-frame.md).

После внедрения хука сводки:

- Доставка сводки и заметок после старта, возобновления и `/compact` — **Г доставки**.
- Содержание сводки — **Гф**: скрипт гарантирует, что данные взяты из git и файлов, а не из памяти
  агента; полноту не гарантирует.
- Обновление заметок, запись решений из чата в артефакты, `/clear` — **Д**.

## Где будет реализовано

- Скрипт сводки состояния и хук SessionStart (`startup|resume|compact`) в `.claude/settings.json`.
- `.agent-state/notes.md`; `.agent-state/` в `.gitignore`.
- AGENTS.md: «решение из чата — в артефакт», «перезаписывай notes.md», «предлагай `/clear` после
  архивации».
- Внедрено 2026-10-07: AGENTS.md «Session state» (чтение роадмапа в начале сессии), `make roadmap-check`.
