# 19. Как агент пишет тексты

**Статус:** принято 2026-10-05, человек. **Область:** 4 «Контекст и инструкции».

## Потребность

Тексты агента — документы, markdown, сообщения в чате — часто непонятны читателю без контекста
разговора: важные пояснения опущены, вода есть, термины не объяснены, текст написан «для своих».
Пример: первые версии документов решений в этой папке ссылались на «пункт 19», не объясняя, что это
номер в очереди вопросов, и использовали сокращения, которые нигде не были расшифрованы. Нужны правила
письма, проверка текста не автором и доставка правил в момент, когда агент пишет.

## Варианты

- Правила письма (стиль-гайд) — договорённость.
- Проверка читателем: свежий субагент без контекста отвечает по документу на вопросы читателя и ищет
  неоднозначности, неявные допущения, противоречия — этап 3 официального скилла Anthropic
  `doc-coauthoring`.
- Официальный скилл `doc-coauthoring` целиком: сбор контекста у человека → разделы с вариантами →
  проверка читателем. Для каждого документа это много раундов вопросов; правил стиля в нём нет.
- Линтеры: markdownlint (форматирование markdown); Vale (линтер прозы: фразы-пустышки, многословие,
  единство терминов — по регулярным выражениям, смысла не понимает).

## Решение

### 1. Правила письма

- **Сначала читатель:** кто читает, что уже знает, что должен понять или сделать после чтения.
- **Суть в начале:** первые 1–2 предложения — что это и зачем.
- **Самодостаточность:** текст понятен без разговора, в котором появился. Термины и сокращения
  объясняются при первом упоминании или ссылкой на глоссарий. Вместо «как обсуждали» — ссылка.
- **«Почему» рядом с «что»;** у цифр и утверждений — источник.
- **Подробность пропорциональна важности:** решения, причины, риски — подробно; очевидное и
  выводимое из кода — не пишется.
- **Пример там, где абстракция.**
- **Конкретность:** без «и т.п.», «различные», «важно отметить».
- **Форма по содержанию:** таблица — сравнение, список — перечень, проза — рассуждение.
- **Один факт — одно место.**

Правила относятся и к сообщениям агента в чате.

### 2. Проверка читателем

Для значимых документов (документы решений, ADR, README, описание архитектуры, proposal): субагент без
контекста по этапу 3 `doc-coauthoring` отвечает по документу на предсказанные вопросы читателя и
ищет неоднозначности, неявные допущения, противоречия. Агент правит и в сводке для ревью
([18 §1](18-human-comprehension.md) п. 9) указывает, что проверка пройдена и что исправлено.

### 3. Скиллы

- **Официальный `doc-coauthoring`** (репозиторий `anthropics/skills`) — ставится при инициализации (ядро, [34](34-core-vs-roadmap.md))
  проекта (команду установки проверить); используется для крупных документов «с нуля» (README,
  описание архитектуры).
- **Свой скилл `writing`** — правила из п. 1 + ссылка на этап проверки читателем из официального
  скилла, без копирования.

### 4. Доставка

Источник правил — `.claude/rules/writing.md`; остальные места содержат выдержки из него:
- `.claude/rules/writing.md` с `paths: **/*.md` — подгружается, когда агент читает или правит
  markdown встроенным инструментом;
- хук-напоминание PreToolUse на Write/Edit `*.md` — пять правил: сначала читатель; суть в начале;
  самодостаточность; «почему» рядом с «что»; подробность пропорциональна важности — и напоминание о
  проверке читателем;
- строка в карте AGENTS.md ([03](03-agent-instructions.md)): «пишешь документ → `writing`; крупный
  документ → `doc-coauthoring`»;
- в AGENTS.md — правила для сообщений в чате: самодостаточность; суть в начале; термины объяснены;
  без воды.

### 5. Линтеры

- **markdownlint-cli2** — в pre-commit для `*.md`.
- **Vale — пока нет:** главное (пропущенный контекст) он не ловит, даёт ложные срабатывания и
  провоцирует механические правки. Добавляется с маленьким списком фраз-пустышек, если вода будет
  пролезать после правил и проверки читателем (пятый принцип, [01](01-process-frame.md)).

## Обоснование

- Систематических данных о раздувании документации нет; косвенно — склонность моделей к длинным
  ответам и то, что агент не знает, что знает читатель; не документировать выводимое, руками писать
  «почему» и подводные камни ([ч.3 п.9](research/report/03-weaknesses.md),
  [ч.6 «Документация»](research/report/06-context-security-docs.md)).
- Проверка не автором сильнее самопроверки ([ч.3 п.12](research/report/03-weaknesses.md));
  этап «Reader Testing» —
  [anthropics/skills: doc-coauthoring](https://github.com/anthropics/skills/tree/main/skills/doc-coauthoring),
  прочитан 2026-10-05.
- Каналы доставки и их ограничения — [03](03-agent-instructions.md).
- Наблюдение человека о качестве текстов агента и пример из этой папки — исходный сбой.

## Гарантия

- Правило по путям — **Г доставки** при чтении или правке `*.md` встроенным инструментом; после
  `/compact` и при записи через Bash не гарантировано ([03](03-agent-instructions.md)).
- Хук-напоминание — **Г доставки** в момент правки; AGENTS.md — **Г доставки** всегда.
- Выполнение правил — **Д**; проверка читателем — **В**; итог — **Ч**.
- markdownlint — **Г** (форматирование).

## Где будет реализовано

- `.claude/rules/writing.md`, `.claude/skills/writing/`, установленный `doc-coauthoring`.
- Хук-напоминание в `.claude/settings.json`.
- AGENTS.md: строка в карте, правила для чата.
- markdownlint-cli2 — в pre-commit.
