# Безопасность: OWASP ASVS 5.0.0, уровень 1

Какие требования стандарта OWASP ASVS (стандарт требований к безопасности веб-приложений) уровня 1
относятся к этому API и чем каждое закрыто. Выборка — задача 2.4 изменения `architecture-kickoff`,
классификацию принял владелец 2026-10-07 (решение [14](../pre-init/14-code-security.md)). Пометка
«запланировано» — проверки ещё нет, указано, где она появится.

Источник: ASVS 5.0.0, тег
[`v5.0.0_release`](https://github.com/OWASP/ASVS/releases/tag/v5.0.0_release) (2025-05-30), файлы глав
`5.0/en/0x10…0x26`. На уровне 1 — 70 требований; тексты ниже — краткий пересказ, дословно — в
источнике.

## Принятые риски

- **Нет авторизации:** любой клиент видит и меняет все задачи и статусы. Задание прямо исключает
  сложную авторизацию (`docs/task/assignment.txt:141`); принято владельцем.
- **Нет TLS:** API работает по HTTP на localhost. Деплой вне рамок; при реальном развёртывании TLS
  обязателен (V12, V3.4.1).

## Политика уязвимых зависимостей (V15.1.1)

Любая известная уязвимость в зависимостях Composer блокирует слияние: `composer audit` входит в
`make check`, который запускают pre-commit и CI. Срок устранения — до слияния следующего PR. Базовые
образы Docker закреплены по digest; перед сдачей они пересобираются на актуальном digest.
